# 三级逐位一致验证链（NumPy 参考 → HLS → 板上）

## 适用场景

PL 上跑的是整数 / 定点计算（量化网络、图像算子、后处理），需要证明"板上输出和设计意图完全一致"，
并且以后每次改 HLS 核、换比特流、改 PS 驱动都能快速复查。

## 使用方法

1. **写一个与硬件逐位一致的 NumPy 参考实现**：按硬件的整数位宽、舍入、饱和、累加顺序写，而不是按浮点模型写。
   它是唯一的"金标准"，后面每一级都和它比。
2. **生成测试向量**：用参考实现对若干真实输入跑一遍，保存输入、每层中间结果和最终输出（二进制文件 + manifest.json）。
   向量要覆盖边界情况（全零、饱和、裁剪边缘、不同尺寸）。
3. **HLS 级**：C 仿真（csim）与 C/RTL 联合仿真（cosim）都读这批向量，逐字节比较，任何一个字节不同即失败。
4. **板级**：PS 程序把同一批输入送进 PL，读回结果逐字节比较；同时在 PS 上用纯 C 再算一遍作为对照。
5. **部署前导出时自检**：每个量化模型导出时自动跑一遍参考实现并写 `verify_report.json`；
   运行时安装的程序包在注册前先在 PL 上自检一次，结果不一致就拒绝注册。

判定只有一条：**逐位相同才算通过**，不使用"误差小于 x"的容差。

## 失效条件

- 存在浮点环节（例如体积、EF 等用浮点计算的指标）：这部分只能做容差比较，本作品中容积计算就不是逐位一致的，
  因此用"同一份 C 代码在主机上编译成动态库作参考"代替 NumPy；
- 主机与板上的数学库实现不同（例如 MinGW 的 `fma` 舍入与 ARM 不同）：需要统一编译选项（本作品为主机库加 `-mfma`）；
- 联合仿真内存需求大（eltwise 核约 17 GB），不能同时跑两个。

## 已验证效果

- 30 节点 U-Net 整网 512×512 板上输出与参考逐位一致；模型库 0–22 号每个程序都有逐位验证记录；
- PL 后处理核 `pp_layer` 182 个向量逐位一致；关键帧引擎 40/40 段视频板上与主机参考逐位一致；
- 5000 帧混合模型稳定性测试 0 个不一致；
- 多次比特流升级（e2b → pp → r1a → r2 → f150 → f150nv）都靠这套向量在几分钟内确认功能未变。

## 来源

- 早期只比较分割 Dice，掩码"看起来一样"，实际有一层的舍入方式与参考不同，换输入后才暴露；
- 一次 HLS 重新综合用到了 `solution1/impl` 里遗留的旧 RTL，csim 通过但板上结果不对——因此要求板级也读同一批向量；
- 浮点体积在主机和板上差最后几位，曾被误判为"板上算错"，于是把"哪些环节能逐位一致、哪些不能"写进了验收口径。

实例：`medical_fpga/embedded/pynq/`（整网 NumPy 逐位参考），`tcp_image/tcp_image_rx/ai/pp_hls/`（HLS 核 + 向量），
`*/deploy/*/verify_report.json`（导出自检），`tcp_image/tcp_image_ui/verify_board_*.py`（板级比对）。
