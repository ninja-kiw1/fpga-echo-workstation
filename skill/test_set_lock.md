# 测试集预注册与冻结

## 适用场景

用公开数据集评价模型 / 算法，且开发周期长、会反复调参：需要保证最终报告的测试集数字没有被"看着测试集调过"，
并能向评委证明这一点。

## 使用方法

1. **划分时就锁定**：TRAIN / VAL / TEST 划分写成文件；没有官方划分的数据集按固定规则（目录、病人编号）划分后不再改动。
   同一病人的多条记录只能落在一边。
2. **开发期间只用 VAL**：所有阈值、超参数、后处理规则都在 VAL 上定。
3. **预注册**：评测前生成 `prereg.json`，记录要评的指标、判定口径，以及模型权重、配置、评测脚本的 sha256。
4. **只评一次**：评测脚本开始时检查锁文件（`lock.json` / `test_set_used.txt`），已存在就拒绝运行；
   评测结束写入锁文件和结果。
5. **报告注明**：哪些数字来自 TEST（只评一次）、哪些来自 VAL。

## 失效条件

- 数据集之间有隐藏重叠（例如 TED 数据集的病例其实是 CAMUS 训练集的子集）：必须先做去重检查，否则"外部测试"不成立；
- 预注册之后发现评测脚本有 bug：只能如实记录并说明，不能改完再评一次。

## 已验证效果

- 四个测试集（EchoNet-Dynamic、CAMUS、CardiacUDA、HMC-QU）在预注册 33 个文件哈希后各评一次，结果见 `final_test_2026-10-25/`；
- 去重检查发现 TED 的 94 例与 CAMUS 训练集重合、4 例与 CAMUS 测试集重合，这 4 例被排除。

## 来源

开发中途曾想"在测试集上看一眼"以确定阈值，讨论后改为只在 VAL 上定阈值，并把这条规则做成了脚本里的硬检查。

实例：`final_test_2026-10-25/prereg.py`，各线 `results/final_test/` 下的锁文件。
