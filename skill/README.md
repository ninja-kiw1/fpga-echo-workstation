# 技能包（skill/）

校验脚本、案例模板（流程模板）、踩坑清单。每一项都写明**适用场景、使用方法、失效条件、已验证效果**，以及**是从哪些失败或观察中总结出来的**。

## 通用性说明

- 上面各项不依赖本题目（心超 / 医学影像）：只要是"Zynq / Zynq UltraScale+ 板 + PS 端 Linux 服务 + PL 端 HLS 加速核"的作品都可以直接套用，
  换板卡时只需改板子地址、器件型号和时钟数值。
- `check_repo_names.py` 完全通用，任何仓库都可以跑。
- 各项中引用的本仓库路径只是"已验证的实例"，不是使用前提。

## 与大模型协作的方式（这些经验是怎么来的）

本作品大部分代码、脚本和验收流程是在与 Claude Code 的对话中完成的。上面每一条都对应一次或多次"模型给出方案 → 上板失败或结果不对 →
定位原因 → 把原因固化成脚本 / 检查项"的循环；各文件的"来源"一节写明了具体是哪次失败。协作中反复验证有效的提示方式：

1. **先要证据再改代码**：要求模型先读日志 / 寄存器 / 报告给出判断依据，再动手修改（见 pitfalls.md 第 1、5 条，都是"看起来像代码问题，其实是环境问题"）。
2. **每一步都要可回滚**：要求所有上板改动先写回滚路径，再执行（board_deploy_rollback.md）。
3. **用逐位一致代替"看起来差不多"**：只要有整数参考，就要求逐位比对，不接受容差（bit_exact_verification.md）。
