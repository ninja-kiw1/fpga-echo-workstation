## 方案（10-10 定，训练前写下）

**目标**（总框架 ③，应用层）：整段心超视频在 FPGA 上逐帧分割左心室，PC 上做多心动周期分析——逐拍找舒张末（ED）和收缩末（ES）、逐拍算 EF、心率、质控、事件时间线、点击纠正、证据报告；
在官方 TEST 1,277 段上评测（**只评估一次**），并与已发表结果对比。

**上板输入链**（`common.py`）：AVI 帧（112×112，三通道几乎相同）→ 灰度 (B+G+R+1)//3 → 四周各补 8 像素 0 → 128×128 紧凑帧 → 板子 128 档 →
logit 裁回中间 112×112，就是原始网格，**全程不重采样**。新模型放进模型库（16 号起），只能经紧凑帧调用。

**分割模型的两个候选**（同一个 34,201 参数的 U-Net，训练预算相同；TRAIN 7,465 段的 ED、ES 帧，共约 14,930 帧）：
- `rep`：R = G = B = 本帧；
- `t3`：R / G / B = 前约 40 ms 的帧 / 本帧 / 后约 40 ms 的帧（偏移 = round(0.04 s × 帧率)，至少 1 帧，到头就夹住），给二维网络一点运动信息。
增广：旋转 ±15°、缩放 0.85–1.15、平移 ±8%、亮度 / 对比度 / gamma（与 CAMUS 相同）；不翻转（心尖四腔的左右有约定）。
**选择规则**：VAL 1,288 段的 ED、ES 帧平均 Dice 最高者（原始 112 网格，logit > 0）。量化规则与其他模型相同。

**逐拍 EF**（PC 上，`beats.py`，在训练集上定参数，VAL 上看效果）：
1. 每帧掩膜取最大连通块、填洞，用单平面圆盘法（20 个圆盘，沿用 F4 的 `ef_simpson.diameters`，像素单位；EchoNet 没给像素尺寸，EF 与尺度无关）算容积 V(t)；
2. V(t) 上找峰（ED）和谷（ES），最小间隔和显著性按帧率定；每个“ED → 下一个 ES”算一拍的 EF，整段取各拍平均；
3. 线性校准 EF_真 = a·EF_测 + b，**只用 TRAIN 的 1,500 段**拟合（与“校准只用训练集”一致）。
- 天花板参照：直接用专家描记线（圆盘法）算出的 EF 与 FileList 的 EF 之间的误差。
- “实时”的含义：板子每秒约 25.8 帧，EchoNet 视频多数 50 帧/秒，所以实时模式每 k 帧分析 1 帧（k = ⌈帧率 / 25⌉），能跟上采集速度；全帧模式每帧都算。两种都报告。

**质控**（PC 上）：逐帧看分割是否为空、清理前有几个连通块、面积是否突变、边界附近 logit 的置信度；逐拍看 EF 的离散程度。
用 VAL 检验质控是否有用：标记出来的视频 EF 误差是否明显更大（例如去掉最不可信的 10% 后，平均绝对误差下降多少）。

**指标与对照**：
- 分割：ED / ES 帧 Dice（原文 DeepLabv3 约 0.92，ED 约 0.93，ES 约 0.90）；
- EF：平均绝对误差、均方根误差、R²（原文视频模型 + 逐拍平均，测试集平均绝对误差约 4.1%）。我们只用分割 + 几何，不训练 EF 回归网络；
- 速度：每段视频的板端时间、每秒帧数、相对视频自身帧率的实时倍数。

已发表结果出自 Ouyang et al., Nature 2020，数字以原文为准，引用时再核对。

## 结果（开发阶段，VAL；TEST 未动）

**数据准备**（`prep_echonet.py`）：TRAIN 7,459 段 / VAL 1,288 段有 ED、ES 描记（TRAIN 6 段无描记被去掉）；整段视频缓存 VAL 228,836 帧、TEST 226,460 帧、TRAIN 子集 1,500 段 260,358 帧。
直接用专家描记线（圆盘法）算 EF 与 FileList 的 EF：0.7% 的视频描记行顺序异常（“收缩末”容积反而更大），去掉后平均绝对误差 0.85、r = 0.996——
FileList 的 EF 就是这样从描记算出来的，所以 EF 走圆盘法是对的。

**容积算法**（`volume.py`，在训练集的专家掩膜上比较）：

| 方法 | EF 平均绝对误差 | r | 速度 |
|---|---:|---:|---|
| 专家描记线直接算（天花板） | 0.85 | 0.996 | — |
| **掩膜 + 主轴方向 20 个圆盘（采用）** | **1.18** | **0.990** | 1,500 段 1.7 s |
| 掩膜 + F4 的 CAMUS 双平面法单平面版（放大 4 倍） | 1.62 | 0.980 | 慢约 250 倍 |

CAMUS 那套找二尖瓣平面的 8 像素阈值是按大图定的，112×112 的小掩膜上不合适。

**1. 输入编码**（`train_echonet.py` → `results/selection_input.json`）：`t3` 0.9059 / `rep` 0.9056（VAL ED+ES 帧 Dice），按规则选 `t3`，但差别只有 0.0004——
与 CT 不同，心超里前后帧几乎没带来好处。`t3`：ED 0.923、ES 0.889，最差 5% 帧 0.80。

**2. 量化**（`quantize_echonet.py`）：浮点 0.9059 → 全 INT8 0.9049 → 混合精度 **0.9066**（INT16 节点 `first_block_2` + `add`，与 CAMUS 左心室模型相同）。

**3. 位级验证**（`export_verify_echonet.py` → `deploy/t3/verify_report.json`）：金标准帧 30 个节点、VAL 全部 2,576 个 ED/ES 帧、512 整表，0 差异。

**4. GPU 上的整数参考**（`int8_gpu.py`）：几十万帧视频要跑整数模型，CPU 太慢。改成 GPU 上 float32 的 im2col + 矩阵乘（关掉 TF32），
INT16 层的输入拆成高低字节分别卷积，保证每个乘积和部分和都是 2^24 以内的整数，所以结果精确；与 CPU 参考在 2,576 帧 + 441 帧视频上逐值相同，每帧 5.2 ms。
（先试过直接用 cuDNN 的 float32 卷积：某些批次 cuDNN 选了 Winograd 之类的变换算法，结果不再是整数，被完整性检查拦下——这也说明大于 2^23 时这种检查不够，所以改成只用乘加。）

**5. 逐拍参数与校准**（`tune_beats.py`，只用 TRAIN 子集 1,500 段）：最小谷间距 0.4 s、显著性 0.3、ED 搜索窗 0.9 个周期、各拍取中位数、不平滑；
校准 EF = 0.839·EF_测 + 7.58（全帧），0.827·EF_测 + 9.19（实时）。训练集内平均绝对误差 5.07 / 5.11。
试过、没采用（都按训练集判断）：百分位法 EF（1 − P5/P95 等）和三特征线性组合（训练集 5 折交叉验证不如逐拍中位数）；
去掉 ED 落在视频第 1 帧的拍（训练集 5.07 → 5.17，反而变差）。

**6. VAL 上的 EF（浮点模型的特征，整数版本稍后补）**（`eval_ef.py` → `results/ef/t3_fp32_val.json`）：

| 方式 | EF 平均绝对误差 | 均方根误差 | R² |
|---|---:|---:|---:|
| 全帧，逐拍中位数 + 校准 | 5.40 | 7.38 | 0.64 |
| **实时（50 帧/秒的视频隔帧分析）** | **5.35** | 7.30 | 0.65 |
| 诊断：只用描记的那两帧（不做逐拍） | 7.85 | 12.33 | 0.00 |
| 天花板：专家描记线直接算（描记正常的视频） | 0.86 | 1.16 | 0.99 |

- 实时模式不损失精度；逐拍取中位数很关键（单帧的分割误差直接算 EF 误差 7.9）。
- 质控：质控分最高的 10% 标记出来后，其余视频平均绝对误差 5.40 → 5.10，被标记的视频 8.15。
- 参照（原文，不同方法）：EchoNet-Dynamic 用视频网络 R(2+1)D + 逐拍平均，测试集平均绝对误差约 4.1。我们只用 34,201 参数的分割网络 + 几何，
  在 FPGA 上每秒 25 帧，误差大约多 1.3 个百分点。

**7. 整数模型（= 板上）的逐拍参数与 VAL 结果**：在 TRAIN 子集的整数特征上重新定参数（比浮点多了 3 帧中值平滑，其余相同），
校准 EF = 0.812·EF_测 + 10.51（全帧）、0.785·EF_测 + 14.06（实时）；质控门限取 TRAIN 子集质控分的 80 / 95 百分位（0.885 / 1.304）。

| VAL（整数） | EF 平均绝对误差 | 均方根误差 | R² |
|---|---:|---:|---:|
| 全帧 | **5.42** | 7.40 | 0.64 |
| 实时 | **5.49** | 7.43 | 0.64 |

质控：标记质控分最高的 10% 后，其余视频平均绝对误差 5.14，被标记的 7.86（质控分与误差的秩相关 0.17，弱但有用）。

**8. 点击纠正：直接复用 CAMUS 的点击模型（3 号）不行**（`eval_click_reuse.py` → `results/click_reuse.json`，VAL ED+ES 帧）：
从 EchoNet 模型的结果（Dice 0.907）出发，0 次点击时 3 号模型反而把结果拉低到 0.856，点 3 次才超过起点（0.919），5 次 0.935；
在 CAMUS 上同一个模型第 1 次点击就从 0.921 升到 0.941。差别来自数据域不同，要用的话得为 EchoNet 另训点击模型。工作站暂不提供点击纠正。

## 工作站界面（`tcp_image_ui/echowin.py` + `echo_ws.py`）

主界面「心超工作站…」按钮或 AI 菜单 →「打开视频…」选 EchoNet 的 .avi →「开始分析」：
- 左：视频逐帧显示 FPGA 分割的左心室轮廓，ED / ES 帧标出；
- 右上：容积曲线，▲ 舒张末、▼ 收缩末，每拍标 EF；右中：事件时间线（每个心动周期一段、每个分析帧一个质控小格：绿正常、黄不连通 / 低置信、红空 / 碰边）；
- 右下：EF（逐拍中位数，已校准）、心率、质控结论（通过 / 注意 / 不可靠）和原因、逐拍列表；有 FileList 时显示数据集标注 EF 作对照；
- 实时模式按视频自身节拍送帧（模拟边采集边分析），状态栏给实时倍数和最后一帧的滞后；全帧模式尽快跑完；
- 「生成证据报告」：HTML 一页（结论、容积曲线、逐拍表、关键帧、计算过程、声明），图片内嵌，存到 `tcp_image_ui/reports/`。
不连板自检 `_verify_echowin.py`（假板子回放整数输出）：两种模式负载逐字节相同、报告能生成。

v5.8 回归（日志 `tcp_image_ui/board_check_v5/regression_v58/`）：心超分割与模型切换、点击纠错、序列传播、配准、实时通路、8 个算子程序、CT 两阶段、1000 帧稳定性，全部通过。
