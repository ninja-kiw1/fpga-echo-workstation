# pp_hls：PL 后处理流水线原型（2026-10-12）

可行性分析见 `../../docs/pl_postprocess_pipeline_feasibility_2026-10-12.md`。这里是那份分析的第一步：**HLS 原型 + 逐位验证 + 综合**。
还没有接进 BD，也没有上板。

## 它做什么

`pp_layer` 是第三个 HLS 算子，和 conv/eltwise 一样，通过 m_axi 读张量 BRAM 里最后一层的 logit（每像素一个 128 位字，取第 0 通道的低字节）。
功能由 `op` 选择：

| 位 | 功能 | 对齐的现有实现（golden） |
| --- | --- | --- |
| — | 掩膜：`k=1` 时 `logit ≥ thr`；`k=2/4` 时双线性放大后 `> tn/2`（整数实现） | `ct_volume.upsample_bilinear` |
| — | 像素数、连通块数（4 连通，`PP_CONN8` 时 8 连通）、最大块面积 | 板端 `ai_view_count`、scipy |
| `PP_TILES` | 4×4 分块和（F5 配准） | `ai_view_fill_reg` |
| `PP_CLEAN` | 保留最大连通块（面积相同时取光栅顺序最先出现的）+ 填洞 | `echo_ws.clean` |
| `PP_MASK` | 输出位掩膜（每行补齐到 128 位整字，和 v6c 位掩膜同序） | — |

另外支持在窗口 `(x0, y0, cw, ch)` 内处理，用于 EchoNet 从 128 裁出中间的 112。

**算法**：连通块标记只扫一遍，用"局部规则"给临时标号，用并查集合并，根永远是最小标号，所以根就是该块光栅顺序上的第一个像素（和 scipy 的编号一致）。
后面几遍重放同一规则，再用压平后的表把临时标号映射到所属的块，所以**不需要存整幅标号图**。
标号表 4096 项：真实数据最多用到 1815 项（眼底），人工难例最多 3278 项；超出会置溢出标志，交给 PS 兜底。

## 测试向量（174 个）

- 人工难例 10 种 × 4 种用法：螺旋、梳子、嵌套 U 形、棋盘、对角线、带洞圆环、噪声、全空、全满、面积相同 + 单像素洞。
- 眼底：5 张 STARE 样例，512，阈值 -3，4 连通和 8 连通。
- CT：训练集 spleen_2、spleen_3（不碰测试集），×4 和 ×2 放大。
- 心超：3 段 EchoNet 验证集视频，112 裁剪 + 清理。

真实数据的 logit 都用 HLS 逐位参考推理生成，和板上的输出相同。

## 结果（v2，每拍一个像素）

v1（`src/pp_layer_v1.cpp.txt`）每行依次跑五个循环，并查集在像素循环里做，平均每像素约 9 拍。
v2 把每行合成一个 II=1 的循环：临时标号只看邻居、不查并查集；每个像素最多记一条等价关系（其余都已被前面的像素蕴含），
行末统一合并；面积按游程记，行末加进表；行缓冲按行号奇偶交替使用，不再复制；512 整帧时分块和顺带在第一遍算出。结果与 v1 逐位相同。

| 项 | v1 | **v2** |
| --- | --- | --- |
| 原生 g++ / Vitis C 仿真 | 174/174 | **182/182**（新增 V 字形、锯齿两类 8 连通难例；17 个还和板端 `ai_view_count` 对过） |
| 测试有效性（故意改坏） | 2 个改坏版本都被抓到 | 5 个都被抓到：去掉"左 + 右上"合并 → 7 个失败；去掉"左上 + 右上"合并 → 3 个失败；行末面积不累加 → 157 个；背景边界标记写错 → 106 个；不记等价关系 → 145 个 |
| C/RTL 协同仿真（3 个代表用例） | 通过 | **通过** |
| 像素循环 | 不流水 | **II=1**（流水深度 18） |
| 眼底 512：计数 + 分块和 + 掩膜 | 240 万拍 = 24 ms | **36.7 万拍 = 3.67 ms**（每像素 1.4 拍） |
| 心超 112：保留最大块 + 填洞（三遍） | 53 万拍 = 5.3 ms | **5.7 万拍 = 0.57 ms** |
| CT 128→512：×4 放大 + 掩膜 | 233 万拍 = 23 ms | **34.0 万拍 = 3.40 ms** |
| 对照：板上 PS 跑 512 眼底计数（单核 A53） | 4.5 ms | 4.5 ms → v2 **快 1.2 倍**，而且不占 CPU |
| Vivado OOC 综合（100 MHz） | LUT 8 561，FF 8 105，DSP 23，BRAM 15 块，5.85 ns | **LUT 7 652，FF 9 799，DSP 19，BRAM 11 块（4 个 RAMB36 + 14 个 RAMB18），6.32 ns** |
| 并进现有设计（估） | BRAM 203/216，LUT 约 81% | **BRAM 199/216，LUT 约 80%，DSP 281/360** |

## 已知问题和下一步

- 每像素 1.4 拍里多出的 0.4 拍来自每行的启动开销（流水深度 18）、行末的合并和面积累加、×4 放大时重新装源行。
  把行末工作和下一行的扫描重叠（dataflow）可以再接近 1 拍，但收益已经不大。
- 接进 BD：`ai_data_ic` 加两个主口（`gmem_in` 读、`gmem_out` 写），调度放在最后一层卷积之后。
  由于 logit 已经在张量 BRAM 里，读回从"4 MB 的最后一层张量"变成"几 KB 的结果 + 位掩膜"。
  然后按现有流程跑 17 个程序回归。
- 注意：这一步要改比特流，按惯例先在本机完整构建、检查时序，再上板，并保留回退链。
- 跑 `evaluate` 前要先删 `ai/build/pp_ip/solution1/impl`，否则导出目录会混入上一版的文件（踩过一次）。
