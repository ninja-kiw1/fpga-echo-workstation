# FPGA 侧图像处理设计说明

> 本文是 `tcp_image_rx` 项目新增的 **PL 侧图像处理**部分的设计文档。
> 前面的网口收图 / DDR 存储 / AXI DMA 部分见同目录的 `design_notes.md`。

---

## 1. 目标

在 PL 里对收到的 512×512 图像做四种处理，并支持一种组合模式；处理后的图回传给 PC：

| 模式 | `ctrl[2:0]` | 处理 |
| --- | --- | --- |
| 灰度归一化 | 3'd0 | RGB→灰度，再按整帧 min/max 线性拉伸到 0..255 |
| 阈值分割 | 3'd1 | RGB→灰度，`g >= thr` 取 255，否则 0 |
| 边缘增强 | 3'd2 | RGB→灰度，Sobel 梯度幅度 \|gx\|+\|gy\| |
| 伪彩色映射 | 3'd3 | RGB→灰度，查 jet 彩虹表 |
| 组合 | 3'd4 | 先归一化，再把归一化结果查 jet 表 |
| 原图直通 | 3'd5 | **不走 PL**：PS 直接把收到的原图回传 |
| **边缘叠加** | 3'd6 | **PL 里没有这个模式**：PS 让 PL 跑模式 2 拿边缘图，再把"边缘 >= 阈值"的像素在**原图**上画成白色 |

> **模式 6 为什么放 PS**：它只是把已有的两张图叠起来，和 AI 掩膜叠加
> (`ai_view_overlay_rgb`) 是同一套做法；原图 PS 手里本来就有（`rx_buf`），
> 所以只多花一趟 PL 往返，**不用改 RTL、不用重出比特流**。
> 阈值沿用控制头里的 `thr` 字段（模式 1 是"灰度门限"、模式 6 是"边缘门限"）。

**切换方式**：板子上没有用户按键（`hardware_info.txt` 无引脚定义、无 `/dev/input`、
设备树无 `gpio-keys` 节点，三重确认过），所以按约定**由 PC 端选择**，经 TCP 控制字
传给 PS，PS 写进 PL 的模式寄存器。

## 2. 数据通路

```
     DDR 输入缓冲 (32bit/像素)          DDR 输出缓冲 (32bit/像素)
            │                                   ▲
            │ AXI DMA MM2S                      │ AXI DMA S2MM
            ▼                                   │
   S_AXIS ──► RGB→灰度 ──► [ 帧缓冲 262144×8 ] ──► 3×3 窗口 ──► mode_map ──► M_AXIS
   (32bit)    (77/150/29)    写入时统计 min/max   读出(1像素/3周期)   五模式映射
```

**为什么是全帧缓冲？** 归一化需要整帧的 min/max，纯流式单趟拿不到。
ZU3EG 有 9.4 Mb BRAM，缓冲一帧灰度只要 2 Mb，换来"一次 DMA 就够"，
比跑两趟 DMA（先统计再映射）干净得多。

**流控**（不丢像素的关键）：
- 输入侧 `s_axis_tready = 帧缓冲可写 && 灰度流水级空`，收帧期间恒高，只在读出阶段拉低。
- 输出侧读出是自由跑的（1 像素 / 3 周期），但 `m_axis_tready` 一拉低就用 `hold`
  把**帧缓冲的读出和 mode_map 的流水线一起冻住**，等下游取走再继续。

## 3. 接口约定

### 3.1 DDR 里是 32bit/像素，不是紧包 RGB888

TCP 协议传的是紧包 RGB888（3 字节/像素），但 **DDR 缓冲里必须放成 32bit/像素**：

```
31      24 23      16 15       8 7        0
┌─────────┬──────────┬──────────┬──────────┐
│  8'h00  │    R     │    G     │    B     │
└─────────┴──────────┴──────────┴──────────┘
```

原因：AXI DMA 按 4 字节搬运，紧包的 3 字节/像素会让像素**跨 beat 边界**，
PL 侧根本对不齐。转换由 PS 程序做（一次 ~1 ms 的循环）。

### 3.2 DDR 布局（在厂商预留的 1 GB no-map 区里）

| 偏移 | 大小 | 用途 |
| --- | --- | --- |
| `0x000000` | 1 MB | 输入图（512×512×4） |
| `0x100000` | 1 MB | 输出图（512×512×4） |
| `0x200000` | 64 B | 状态块 `frame_status`（见 `ddr_layout.h`，已扩到 64 B） |

### 3.3 AXI-Stream

32bit/beat，一拍一个像素；`tlast` 标一帧最后一个像素。`tkeep` 全 1（本设计不做字节选通）。

### 3.4 控制字 `ctrl[15:0]`

| 位 | 含义 |
| --- | --- |
| `[2:0]` | 模式 0..4 |
| `[7:3]` | 保留（未使用） |
| `[15:8]` | 阈值（**只有模式 1 用**），默认 128 |

> 2026-10-02 起，**阈值由上位机逐帧下发**（控制头 v4 的第 8 字节，见第 7 节），
> 板端 `--thr` 只作"头里没带阈值时"的默认值。
> **伪彩映射（模式 3）是 `jet[gray]` 直接查表，没有阈值参数** —— 要给它加
> "色带窗口"得改 `mode_map.v`，目前没做。

## 4. 模块清单

| 文件 | 模块 | 职责 |
| --- | --- | --- |
| `rtl/gray_frame_store.v` | `gray_frame_store` | 帧 RAM + min/max 统计 + 3×3 窗口读出，带流控 |
| `rtl/mode_map.v` | `mode_map` | 五种模式映射，三级流水，带流控 |
| `rtl/recip_lut.v` | `recip_lut` | 归一化倒数表 |
| `rtl/pcolor_lut.v` | `pcolor_lut` | jet 伪彩色表（例化两次） |
| `rtl/img_proc_axis.v` | `img_proc_axis` | AXI-Stream 顶层，灰度转换与握手 |

> ⚠ **与 skill 的偏离**：`readable-verilog-generator` 要求每个模块配一个同名
> `<module>_spec.md`。这里改成**一份合并的设计文档**（本节 + 第 5、6 节已覆盖
> 各模块的端口、时序、边界情形与验证用例）。原因是该 skill 本机**只装了 SKILL.md，
> 没有 `scripts/` 也没有 `references/`**，它的门禁脚本、波形渲染、规格校验全都跑不了，
> 拆成多份也无法被它校验；合并成一份对读者更实用。

### 4.1 `gray_frame_store`

- 写侧：`wr_valid`/`wr_pixel`/`wr_last`/`wr_ready`，顺序地址写入，同时统计 min/max。
  每帧第一个像素把 min/max 初始化成它自己；`wr_last` 时把最后一个像素也算进去再发布。
- 读侧：`rd_start` 发起，`rd_valid` 有效时给 9 个抽头的 3×3 窗口，`rd_last` 收尾。
  每个输出像素占 3 个周期（上/中/下三行各读一次），行内 3 级移位得到左/中/右。
- **读地址提前一列**：输出列 `c` 的窗口需要右邻 `c+1`，所以读的是 `c+1`（末列钳位）。
  这样移位后的 `sr2/sr1/sr0` 正好是 `c-1/c/c+1`，**窗口中心对准 `c`**，
  否则整幅图会整体右移一像素。
- 边界处理：行 `y-1` / `y+1` 越界时钳到首/末行（边缘重复），列同理。
- `rd_hold` 拉高时冻结整个读出（状态机、移位、窗口、坐标），供下游背压。
- **陷阱**：帧 RAM 的写**必须放在无复位的 always 块**里。块 RAM 不支持异步复位，
  放进带 `negedge rst_n` 的块会被 Vivado 退化成触发器实现（2 Mb 用 FF 装直接爆）。

### 4.2 `mode_map`

三级流水（输入 1 像素/3 周期，延迟不影响吞吐）：

| 级 | 内容 |
| --- | --- |
| S1 | Sobel 四个方向和（左列/右列/上行/下行）、归一化值、阈值比较 |
| S2 | 由四个和算 `\|gx\|+\|gy\|` |
| S3 | 两张 jet 查表 + 按模式选一 → 输出寄存器 |

`stall` 拉高时冻结全部三级。

## 5. 算法定义（RTL 与本文档必须逐位一致）

> **关于 PC 端参考实现**：原计划在 PC 端用 Python 复刻这几个算法、上板后逐像素比对
> （旧版交接文档里的 ⑦.3）。**用户 2026-10-01 明确取消**：PC 端只负责"发图 + 收 FPGA
> 回传的图"（显示/保存），**不在 PC 上生成参考图**。所以下面这些公式的用途变成
> **"约束 RTL 与两张查表"**，而不是"给 PC 参考实现当规范"。
> 改公式必须**同时改 RTL 里的查表**（表是生成的，见 5.6），否则板子算的和你以为的不一样。

### 5.1 灰度

```
gray = (77*R + 150*G + 29*B) >> 8          // 系数和 256，正好右移 8 位
```

### 5.2 归一化

```
range = (max > min) ? (max - min) : 1       // range=0 时兜底成 1，结果恒为 0
recip = floor(65280 / range)                // 查表 recip_lut
norm  = ((gray - min) * recip) >> 8
if norm > 255: norm = 255
```

不用除法的原因：PL 里做除法又大又慢。查倒数表 + 乘法 + 移位，
逐像素只剩一次 8×16 乘法（被综合进 1 个 DSP48E2）。

### 5.3 阈值

```
thr_val = (gray >= thr) ? 255 : 0
```

⚠ 判据是 **`>=`**：`gray == thr` 算**白**。所以统计"黑"的比例要用 `gray < thr`
（上位机算 Otsu 占比时在这里错过一次，差 1421 个像素）。

### 5.3.1 上位机的自动预设值（Otsu）

`tcp_image_ui/imageio.py` 里做了**两级 Otsu**，灰度用与 PL 完全一致的
`(77R+150G+29B)>>8`，所以在 PC 上算出来的门限就是"板子上参与比较的那个灰度"上的门限。

**算之前先自动定一个"灰度最小值"**（`auto_gray_floor`），低于它的像素当背景、不计入直方图；
灰度为 0/255 的纯黑/纯白也一律不计。规则是"暗半区里第一个**合格**的谷"：

| 判据 | 作用 |
| --- | --- |
| 是局部极小 | 谷才可能是分界 |
| 左侧暗区 ≥ 全图 5% | 挡掉"一圈细黑边"那种假谷 |
| 谷深 ≤ 两侧峰较小者的 30% | 挡掉平坦直方图（渐变图） |
| **暗区贴在图像边框上**（≥30% 边框像素是暗的） | 背景总在边上；画面正中的深色物体不该被剔掉 |

**为什么要"左侧 ≥5%"**：眼底图的暗端不止一个结构——"细黑边(0-3) → 谷(~8) →
深色背景环(16-31) → 深谷(~35) → 内容(48+)"。只看第一个谷会切在 8（只削 3.7%），
筛掉 8 之后才轮到 35（背景环的右沿，削 26%）。

这一切只影响**挑阈值所用的统计**；板子仍然对**全部**像素应用该阈值。
排除得太狠（剩下不到 1/4）时自动退回全量。命令行 `--gray-min N` 可手动指定（0=不排）。

| 级 | 做法 | test.ppm | test_blackborder.ppm |
| --- | --- | --- | --- |
| 自动下限 | 暗半区第一个合格的谷 | **35**（削 26%） | 2 |
| 一级（背景/物体） | 直方图上跑 Otsu | **99**（不排背景则是 71） | **101**（不排背景则是 54） |
| 二级（物体内部） | 把一级以下的桶清零后再跑一次 | **129**（血管） | 131 |

预设填一级（通用图也稳），二级写在提示里供参考。
实测（mode 1，逐帧下发阈值）5 个阈值与上位机独立复算**逐字节 0 差异**；
真机出图对照见 `ai/net/e2e_out/`：`thr_auto.png`（自动 99，血管显形）、
`thr_71.png`（旧的自动值 71，整盘全白）、`bb_auto101.png` vs `bb_thr54.png`。

### 5.4 Sobel

```
col_l = tl + 2*ml + bl      col_r = tr + 2*mr + br
row_t = tl + 2*tc + tr      row_b = bl + 2*bc + br
gx = col_l - col_r          gy = row_t - row_b
mag = |gx| + |gy|           // 约化梯度，不做开方
out = (mag > 255) ? 255 : mag
```

### 5.5 伪彩色（jet）

```
x = i / 255
r = clamp(1.5 - |4x - 3|, 0, 1)
g = clamp(1.5 - |4x - 2|, 0, 1)
b = clamp(1.5 - |4x - 1|, 0, 1)
每分量取整: round(v * 255 + 0.5)
```

### 5.6 表生成

两张表（`recip_lut` 的 256×16、`pcolor_lut` 的 256×24）都是**生成**的，
不是手写。计算公式就是上面 5.2 与 5.5。改公式必须**同时重新生成这两张表**
（表在 `rtl/recip_lut.v` / `rtl/pcolor_lut.v` 里），否则板子算的和你以为的不一样。

### 5.7 边缘叠加（模式 6，**PS 侧组合**）

```
edge = Sobel(灰度(原图))            # 这就是 PL 的模式 2，原样复用
out[i] = (edge[i] >= thr) ? 白(255,255,255) : 原图[i]
```

在 `tcp_image_server.c` 里：把发给 PL 的模式**按 2 发**（`CTRL_MODE_EDGE_PL`），
拿到边缘图后调 `ai_view_edge_overlay(rx_buf, tx_buf, tx_buf, thr, 512*512)` **就地**叠加
（先读后写同一像素，安全）。原图就是 `rx_buf`，不用再过一遍 PL。

* 阈值沿用控制头里的 `thr`（模式 1 是灰度门限、模式 6 是边缘门限）。
* 白色是选定的高亮色；想换颜色改 `ai_view_edge_overlay` 里那三个 255 即可。
* 上位机对模式 6 的"自动阈值"用的是 **Sobel 幅度的 92 分位**（≈8% 的像素画白）——
  边缘幅度直方图极度偏向 0，Otsu 会被压得太低、满屏都是边；
  分位数可控且直观。再取个下限 24 防止平坦图乱画。

**验证（2026-10-02，真机）**：用**板子自己**的边缘图在 PC 上复算叠加，
与板子回的叠加图 **0 / 786432 字节差异**；自动阈值 42 → 画白 8.5% 的像素。
参考：PC 端 Sobel 与板子 Sobel 逐值相同 99.2%、**阈值判决一致 100.0%**。

## 7. 板端 PS 程序（`tcp_image_server`）的改造

> 2026-10-01。目的：让 PS 把 PC 选的模式真正送到 PL、跑完 DMA 往返，并把**处理后的图**
> 回传给 PC —— 也就是"PC 只读 FPGA 回传数据"这句话里，板子该做的那一半。

### 7.1 新增 / 改动的文件

| 文件 | 变化 |
| --- | --- |
| `src/axigpio.h` / `src/axigpio.c` | **新增**：AXI GPIO 最小驱动（ch1 写模式寄存器，ch2 读回帧 min/max） |
| `src/ddr_layout.h` | `frame_status` 扩到 64 B（加 `s2mm_status` / `mode` / `proc_min` / `proc_max` + 16 B 保留） |
| `src/tcp_image_server.c` | 像素格式扩展、模式寄存器、DMA 往返、回传处理图（见 7.2） |

### 7.2 每帧的处理流程（**顺序不能变**）

1. 收 4 字节控制头 → `frame_mode`；收 512 个行包 → 紧包 RGB888 落在 `rx_buf`；
2. **`expand_rgb888_to_ddr()`**：紧包 3 B/像素 → DDR 里的 32 bit/像素 `{8'h00,R,G,B}`。
   ⚠ 必须在启动 DMA **之前**做完 —— MM2S 直接从输入图区读。
   （旧代码把这次拷贝放在 DMA **之后**，是个一直没暴露的 bug：因为一直跑 `--no-dma`。）
3. 写**模式寄存器**：`ctrl = (mode & 7) | (thr << 8)` 写进 AXI GPIO ch1。
   必须在推流前写，否则 `img_proc_axis` 会用上一帧的模式。
4. **DMA 往返**（`dma_process_frame()`）：**先架 S2MM，再开 MM2S**。
   S2MM 是"水槽"，没架好就推流会让 PL 的 `m_axis` 背压、甚至丢像素。
   两路都按 `IMG_DDR_BYTES`（1 048 576，32 bit/像素）搬，不是紧包的 786 432。
5. 读 AXI GPIO ch2 拿 PL 统计的帧 `min`/`max`；
6. 发布状态块（其余字段先写、`magic` 最后写）；
7. `--echo` 回传：DMA 成功 → `pack_ddr_to_rgb888()` 把输出图区的 32 bit/像素 还原成紧包
   再发（**行内容变了，行 CRC 必须重算**，不能复用收帧时那份）；没开 DMA → 回显收到的
   原图（复用行 CRC，保持原有 `--no-dma --echo` 行为不变）。

### 7.3 新增命令行参数

| 参数 | 说明 |
| --- | --- |
| `-g, --gpio-addr <hex>` | AXI GPIO 基址；**`0` = 不写模式寄存器**（默认 `0xA0000000`） |
| `--thr <n>` | 模式 1（阈值分割）的**默认**阈值 0..255（默认 128）；v4 控制头会逐帧覆盖它 |

`--echo` 的语义随之明确：**开 DMA 时回传处理后的图，否则回显原图**。

### 7.4 验证状态（如实说明）

## 8. PS↔PL 寄存器通路（`img_proc_axil`）— 2026-10-01

### 8.1 为什么走这条路

实测确认本板 **PL→PS 从口完全不可用**：把 AXI DMA 放进 PL 后，不管挂到
`S_AXI_HPC0/HP0/HP1/ACP` 哪个从口，DMA 启动后 `DMASR` 恒为 0（busy、无任何 error），
跨 2 GB 边界也不报 `DECERR` —— 是"事务根本没人应答"。而 **PS→PL 主口是好的**
（`M_AXI_HPM0_FPD` 读写 PL 寄存器正常）。

于是把数据流掉头：**PS 自己把像素逐寄存器推进 PL，再把处理结果逐寄存器拉回来**，
完全不用 DMA、不用 DDR 图像区。

### 8.2 寄存器映射（基址 `0xA000_0000`，4 KB）

| 偏移 | 访问 | 名称 | 说明 |
| --- | --- | --- | --- |
| `0x00` | W | CTRL | `[2:0]`模式 `[15:8]`阈值；**写入即复位帧计数器** |
| `0x04` | R | STATUS | `[0]`in_ready `[1]`out_full `[2]`proc_busy `[3]`frame_done `[15:8]`帧min `[23:16]`帧max |
| `0x08` | W | IN_PIX | 写一个 32bit 像素 `{8'h00,R,G,B}`；**只有 in_ready=1 时握手才完成** |
| `0x0C` | R | OUT_PIX | 读一个处理后的像素，读走即弹出 |
| `0x10` | R | VERSION | `0x494D_5001` |
| `0x14` | R | DBGPIX | 调试：回读 `in_pix_r`（PL 实际收到的像素） |
| `0x18` | R | DBGCNT | 调试：`{12'd0, tready, in_pending, in_cnt[17:0]}` |

一帧的用法：写 CTRL → 循环 262144 次{等 `in_ready`，写 IN_PIX}
→ 循环 262144 次{等 `out_full`，读 OUT_PIX}。

> ⚠ **绝不能无界自旋**：对 IN_PIX 的 AXI 写在 PL 握手之前**不会完成**，会一直阻塞
> CPU。所以每一处等待都必须有上界（实现里用 ~2×10⁷ 次）。之前把板子从网上弄掉
> 就是无界轮询造成的。
