# 网线连接与现有工程实测（2026-10-08）

结论：现有 `tcp_image` 工程可以在当前电脑与 FZ3B 上运行，已实际完成图像收发、图像处理、512×512 AI 血管分割和上位机 GUI 自检。本次没有更新板端程序或加载新的 FPGA 比特流。

## 连接与运行入口

- 电脑有线网卡：`192.168.1.100/24`。
- 板子：`192.168.1.254`；ping 2/2 成功（2–4 ms），TCP 22 与 5060 可连接。
- 演示入口：上一级目录的 `demo_board.bat`。自动载入 im0002、发送一帧，回传叠加图、掩膜和统计。
- 普通上位机入口：`run.bat` / `run_ui.vbs`。
- 原启动脚本指向另一台电脑的 Vivado Python；已增加本机 `srtp-vision` Python 与配套 Tcl/Tk 的查找。GUI 自检已通过。

## 本次验证结果

| 验证 | 结果 |
|---|---|
| bars、checker、gradient 原图直通 | 每幅 786432 字节，逐字节零差异 |
| 模式 0/1/2/3/4/6 | 均完成收发，512 行齐全，CRC 错误和行序错误为 0；本轮未对每个模式做算法参考比对 |
| im0002，512×512 AI，连续 3 帧 | 掩膜完全相同，预处理/叠加/掩膜均完整回传 |
| 3 帧完整往返 | 695.2 / 696.1 / 694.2 ms（约 1.44 帧/秒，单帧往返折算） |
| 板端 AI 整网 | 约 595 ms，包含板端调度与数据搬运 |
| 工程自带 im0002 标准输入与 golden | 血管掩膜 0/262144 像素差异，阈值 -3 |
| 修正启动器后的 GUI 自动收发 | `GUI_SELFTEST` 成功收到 proc/mask/overlay，并保存图像 |

Golden 校验使用 `medical_fpga/deployment/unet_network/vectors/images/im0002/input.bin` 的原始输入张量，还原 RGB 后发给板子，避免不同缩放方式带来的差异。比对的是最终二值掩膜，未读取旧板端的逐像素 logit。

## 当前限制与发现

1. 板端统计协议为 **v1**。当前本地 UI 中的置信度热力图、ROI、形态指标需要新版板端支持，本轮未部署。常规处理、AI 掩膜与叠加图已实测可用。
2. **连通域数量存在错误**：同一帧 im0002，板端上报 12969，但对回传掩膜做独立 4 邻域统计得到 134；血管像素数均为 16842。当前本地 `src/ai_view.c` 中的遍历栈使用 `uint16_t` 存像素索引，无法覆盖 512×512 的索引范围，与此现象吻合。本轮未修改或部署板端代码，界面的连通域数暂不可作为正确结果使用。
3. 部分 README、部署脚本仍保留原电脑 `E:/fpga/...` 路径。当前已修正 GUI 启动入口；未批量改动其他构建/部署脚本。
