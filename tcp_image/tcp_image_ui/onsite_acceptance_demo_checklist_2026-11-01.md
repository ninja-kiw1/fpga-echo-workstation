## 三、出问题时

- **"连不上 …（peer closed）——流量走了代理 TUN"**：关掉代理 TUN，点「检测连接」。
- **"板子正忙"**：别的窗口（平台扩展、彩排脚本）还连着，把它关掉。
- **纠错放在关键帧模式里演示**（33 帧，PC 约 0.6 s、板端 DP 约 0.9 s）。现场模式也能纠错，但要把后面每一帧都重算：ES000108 的 132 帧在 PC 上约 3 s、DP 上约 8 s（提示条每 10 帧报一次进度），别在现场模式里演示纠错。

- **现场模式中途想停**：点「■ 停止」会断开连接，这一次没有最终结果，重新开始即可。
- **板子死机**：重新上电约 1 分钟，服务开机自启。实在不行就用 `board_check_v5/heartapp_*.png` 和演示视频代替。
- EchoNet 画面只在演示中出现，并标注出处（状态栏右侧会自动显示），数据不随交付包分发。
- **板端 DP 界面要换回老主界面**：`python board_station\deploy_board_station.py rollback`（还原启动器、重启工作站）；
  再换回心超工作站：`... switch`；看状态：`... status`。DP 上要先接好显示器再开机（没接显示器时 Xorg 只有 1024×768，窗口会被截掉）。
- PC 和板子自己的 DP 界面可以同时开：每个任务用完就断开连接，谁先发任务谁用；**别在两边同时点开始**。
- **服务端 v5.25 出问题想退回 v5.24**（扫查时的滚动灯 / 切面会消失，其余功能不变，界面自动适应）：

## 六、问答准备（按方向分组；数字都来自报告或 10-30 真板实测）

**FPGA 设计**

| 问 | 答 |
|---|---|
| PL 里有什么、PS 做什么？ | PL：固定结构的 U-Net 张量引擎（conv / eltwise）+ 预处理 img_proc + 后处理 pp_layer + 配准叠加 vis_layer；PS：条带搬运、关键帧调度、斑点跟踪、EF / 全心测量、通信（§4.1） |
| 为什么数据要 PS 搬？ | 板子出厂 PS 配置下最初没找到可用的 PL→DDR 从口，片上 BRAM 也装不下 512 档一层张量，所以按条带搬进 256 KB 张量 BRAM；10-18 才实测 HP0 64 位可用，来不及重构，写在展望里 |
| 卷积峰值 38.95 GOPS，平均只有 13.85（35.6%）？ | 差在条带搬运和每次启动 IP 约 100 µs 的固定开销；512 整网 292.8 ms 里搬运约 122 ms（§4.6、§6） |
| 资源 / 时序？ | LUT 84.75%、BRAM 79.6%、DSP 85.0%；152.15 MHz（MMCM 倍频），WNS +0.470 ns，单时钟域 |
| 怎么量化？精度掉多少？ | 训练后量化 INT8，最多 2 个敏感节点用 INT16（拆高低字节做两次 INT8，结果是精确整数）；EchoNet 左室 Dice 浮点 0.9059 → 混合精度 0.9066（§4.4） |
| 怎么保证板上算得对？ | 板上输出 = HLS 位级参考 = 离线整数模型，逐位一致；同一输入 200 次一个哈希；pp 182 / vis 592 个测试向量；5000 帧稳定性 |
| 和 CPU 比？ | 同板 A53，结果逐位相同：512 整网 292.8 ms 对 4 核 NEON 565 ms（1.93 倍），FPGA 只占 1 核；128 档 22 ms 对 34.8 ms（§8.2） |
| 功耗多少？ | 整板粗测 8–12 W（含 PS、PL、DDR、外设）；板上没有功率传感器，没分空闲 / 推理状态精确测，只是粗测 |
| 和 GPU（Jetson）比？ | 功耗只粗测（整板 8–12 W），没法公平比能效；我们强调的是边缘板卡上整条链路、确定性延迟和逐位可复现，不和 GPU 比吞吐 |
| 为什么不再提速 / 改比特流？ | 每帧只用 26% 预算、延迟在 80 ms 内；P99 里最大一块是关键帧等后 40 ms 的帧（模型输入方式决定），改比特流也去不掉 |

**临床与精度**

| 问 | 答 |
|---|---|
| EF 误差 5.39，EchoNet 原论文 4.1？ | 原论文是千万级参数的视频网络跑在 GPU；我们是 3.4 万参数、INT8、板上 22 ms；差的约 1.3 个点用区间 + 复核分流兜底 |
| EF ≤ 40 灵敏度才 0.54？ | 单看分档确实低；所以由 80% 保形区间决定复核，160 段 HFrEF 中 98.1% 被判出或标复核，复核率约 50%；未标复核的分型一致率 97.8% |
| 保形区间是什么？ | 在验证集上校准"预测误差的分位数"，给每段一个 80% / 90% 区间，测试集覆盖率 0.80 / 0.89；区间跨过 40 或 50 就不下分档、提示复核 |
| 质量灯怎么来的？ | 不加模型：由分割结果算 9 个规则特征，CAMUS 训练集拟合逻辑回归，验证集区分 Poor 质量 AUC 0.911；只作提示，不参与复核 |
| 标尺怎么自动读的？ | 屏上深度刻度是黄色短线：找黄色小连通块，取共线最多的一串，相邻间距的中位数 = 1 cm，再要求两个长刻度正好隔 5 个间距才算数；HMC-QU 292 段首帧 236 段读出，ES000108 自动 27.80 像素/cm、手点 27.88；读不出就弹框手点 |
| 扫查时的灯和切面准吗？ | 10-31 加的（服务端 v5.25）：质量灯每 0.2 s 用最近 1 s 算一次，和整段质量灯同一算法、板上与 PC 逐位一致，标定只针对 EchoNet 这类画面；切面 = 右室面积 / 左室面积，CAMUS 验证集准确率约 0.84，HMC-QU 两腔片段 4 次只判对 2 次，所以只作提示。真扫查数据（带探头位姿）没有公开的，探头引导是下一步 |
| 节段室壁运动准不准？ | HMC-QU 测试集：节段 AUC 0.78，整段 AUC 0.90；单用 EF 的 AUC 也是 0.90，节段的作用是指出该复核哪一段（界面上写的 0.76 / 0.61 / 0.88 是开发集交叉验证的数） |
| 右室 / 右房？ | CardiacUDA 测试集 Dice 0.776 / 0.877；只给面积比，RV/LV > 1 提示右室扩大（文献多用直径比，只作提示） |
| 能判断什么病？ | 见上面一条；不下诊断，只给提示方向；没有多普勒，看不了瓣膜和舒张功能 |
| ES000108 心率 129，超声机屏上写 96？ | HMC-QU 官方 25 fps，AVI 文件头写 30 fps，我们按文件头计时，心率偏高约 20%（按 25 fps 约 107）；EF、节段是比值 / 形状，不受影响；所以界面不对心率下"偏快"的提示；接采集卡后用驱动时间戳 |
| z4 那段界面 EF 70%，数据集标注 78.5%？ | 单段误差约 8 个点，在测试集误差分布之内（MAE 5.39 是平均）；这段是验证集，不是测试集 |
| 单平面 33% 和关键帧 41% 差这么多？ | Simpson 在二尖瓣平面截断、且没做训练集校准；同一拍未校准的比值法是 38%；单平面只演示"带毫米尺度"的流程，不据此分档 |
