## 载入自己的图片

点「载入图片…」，**任何格式、任何尺寸**都可以。程序会**统一拉伸成 512×512 RGB888**
再发送，**不考虑原始长宽比**。

**Netpbm 全家桶与裸 RGB888 是原生读写，不需要 Pillow**（图像处理/FPGA 圈子里最常用的交换格式）：

| 格式 | 读 | 写 | 说明 |
| --- | --- | --- | --- |
| PPM `P1/P2/P3/P4/P5/P6` | ✅ 原生 | ✅ P6 | ASCII 与二进制都认；`maxval` 1..65535（16 位也能读） |
| PGM `P2/P5` | ✅ 原生 | ✅ P5 | 灰度；写出的灰度用与 PL 相同的 `(77R+150G+29B)>>8` |
| PBM `P1/P4` | ✅ 原生 | ✅ P4 | **1 = 黑**；读时按位打包解析（宽度非 8 倍数也对） |
| PNM `.pnm` | ✅ 原生 | ✅ P6 | 扩展名 `.pnm` 一律按 P6 写 |
| PAM `P7` | ✅ 原生 | ✅ P7 | depth 1/2/3/4；多出来的 alpha 丢掉 |
| 裸 RGB888 `.rgb/.raw/.bin` | ✅ 原生 | ✅ 原生 | 必须正好 786432 字节，原样透传 |
| PNG / JPG / BMP / GIF / TIF / WebP | ✅ Pillow | ✅ Pillow | 需要装 Pillow |

> 分发的时候**先看文件头**再看扩展名：一个 .xyz 文件里装的是 P6，照样能读出来。

其它规则：

| 输入 | 处理 |
| --- | --- |
| 800×400 之类的图 | 转 RGB → **拉伸**为 512×512（优先 Pillow LANCZOS） |
| 已经是 512×512 | **不重采样**，逐字节不变（保证"回图与原图一致"能 bit-exact 比对） |
| 带透明通道 RGBA | 丢掉 alpha，保留 RGB 三通道 |
| 动图 GIF | 取第一帧 |
| 没装 Pillow 又要拉伸 Netpbm | 回退到**最近邻**缩放（纯 Python，仍然能用） |

载入后状态栏会写清做了什么，例如：

```
已载入 test.ppm —— Netpbm P6 512x512 maxval=255 → 尺寸已是 512x512，未重采样（逐字节不变）
已载入 cat.jpg —— 1920x1080 RGB → 已拉伸为 512x512（Pillow LANCZOS）
```

也可以用启动参数预载一张图：

```
run.bat --image D:\pics\cat.jpg
run.bat --image E:\fpga\my_project\tcp_image_ui\test.ppm
```

`test.ppm` 是一张 512×512 的真实眼底图（`../tcp_image_rx/ai/net/make_test_ppm.py` 生成），
拿它测 AI 血管分割最合适。

## 回传内容（flags）

板子现在能按 **flags** 决定回传什么 —— 左侧参数栏「回传内容」那一组复选框：

| 勾选 | 回传的东西 |
| --- | --- |
| **预处理图** | PL 处理后的图（= 老行为，默认勾上） |
| **血管掩膜** | AI 判为血管的像素（白底黑血管图，0/255） |
| **掩膜叠加** | 把掩膜以红色叠在预处理图上 |
| **数值统计** | 图像流之前先回一个 64 字节统计块（血管像素数/占比/连通域/logit 范围…） |
| **置信度** | 再回一幅 **logit 图**（flags b5，排在掩膜之后；每像素 R=G=B=logit+128）。勾它会自动带上「数值统计」 |

**AI 输入**下拉框：`原始 RGB`（模型训练时的输入分布）或 `预处理结果`
（严格按"预处理 → AI"的链路）。两者结果差别很大，可以直接对比。
**AI 判定门限**是血管判据（`logit >= 门限` 判为血管，模型量化阈值是 -3，≈ 概率 0.42），
随每帧发给板子；滑条旁边实时显示它对应的概率。

### 置信度热力图与本地改门限（2026-10-07）

勾上「置信度」后，板子多回一幅 logit 图，右图「显示」里多出两种视图：

| 视图 | 内容 |
| --- | --- |
| `heat` 置信度热力图 | 每像素按血管概率 `sigmoid(logit × 0.1017)` 上色：黑紫 ≈ 0，红 ≈ 0.5，浅黄 ≈ 1 |
| `uncertain` 不确定区域 | 底图上确定的血管涂红，`|logit − 门限| ≤ 不确定带` 的像素涂黄（模型拿不准的地方） |

拖动 **AI 判定门限**滑条或改「不确定带」时，掩膜、叠加、不确定区域和血管占比都在**上位机本地**
按 logit 重算（约 20 ms），**不重跑 FPGA**；提示里会注明“本地重算（板端本帧 x）”。下一次发送时，
新门限再随控制头发给板子。

- **与板端一致**：板端门限下，本地复算的掩膜 / 叠加图与板端回传的逐字节比对，结果显示在提示里
  （“与板端逐字节一致 ✓”）。`_verify_confidence.py` 用板端原样的 `ai_view.c` 做了 30 组离线比对。
- **叠加底图**：板端叠加画在预处理图上；本帧没回传预处理图时，本地叠加改用原图，提示里会注明。
- **老板端**：只有统计块 `version >= 2` 的板端认 b5。老板端不会发 logit 图，上位机据统计块判断，
  不会空等到超时。
- 不确定带默认 ±8（logit 单位，约 ±0.8 个自然对数几率），可按需要调。

### ROI 局部推理（2026-10-07）

在**左图上按住左键拖一个框**就选好了 ROI；右键或 `Esc`（或「AI → 清除 ROI」）清除。之后每一帧：

- 上位机发 **v5 控制头**（v4 + ROI 的 x、y、w、h），自动带上统计块；没勾任何 AI 内容时自动勾「掩膜叠加」；
- 板端只在**裁剪窗口**上跑整网：ROI 每边外扩 24 像素（贴图像边的那侧不扩）、起点对齐到 4、
  尺寸取 8 的倍数（左图青色虚线框就是它，标题处显示占整图的比例）；结果贴回 512×512，ROI 外的 logit 为 −128；
- 右图描出 ROI 框；统计（血管像素、连通域）只算框内；「板端推理」后面注明实际算了多大。

**为什么能保证结果不变**：裁剪边界的零填充最多影响到离边 22 像素的输出（按层表逐算子推导，
NumPy 逐位参考实测也正好是 22），所以留 24 像素后，ROI 内的输出与整图推理**逐值一致**；
起点必须对齐到 4（两级池化），否则连中心也会错。证明脚本：`../tcp_image_rx/ai/net/roi_exactness.py`。

**在板上核对**：勾「置信度」，先对这张图**不框 ROI 发一帧整图**（留作参照），再框 ROI 发送，
状态栏会显示“ROI 与整图推理逐值一致 ✓（n 像素）”。

只有统计块 `version >= 3` 的板端认 v5 头；已知是老板端时上位机自动按整图发，并在状态栏提示。
命令行：`python imagelink.py 192.168.1.254 5060 im0002 --flags proc,overlay,logit --roi 180,150,150,140`。

### 血管形态指标（2026-10-07）

勾「形态指标」（flags b6，自动带上统计块）后，板端在本帧掩膜上算一组指标，界面底部蓝色一行显示：
总长度、平均管径、分支点、端点、段数、迂曲度、分形维数、视野内血管密度（及四象限）、PS 用时；
右图「显示」里多一个 `morph` 视图（血管半透明红、骨架白、分支点红点、端点青点）。

- 整图帧在 AI 分辨率的网格上算，长度 / 管径换算成 512 尺度显示；ROI 帧只分析 ROI 框。
- 指标按**板端本帧门限**算（行首注明门限）；本地拖门限滑条不会重算它们。
- 定义、验证和“哪些指标可信”（与两位专家标注的对比）见 `../tcp_image_rx/docs/vessel_morphology_metrics.md`：
  总长度、分支点数、分形维数、FOV 密度与人工标注的一致性不低于两位专家之间；**平均管径和端点数在模型掩膜上不可靠**。
- 只有统计块 `version >= 4` 的板端认 b6；老板端时这一行会提示“板端程序不支持”。

**分辨率**下拉框：`512 / 256 / 128 / 64 / 32`。AI 现在跑的是**条带调度**，
全分辨率 512 也能算（掩膜是真血管树）。**现在 512 板端整网 599 ms、三幅图全回传时
PC 端往返 698 ms**（2026-10-06 实测，见 `../tcp_image_rx/progress_and_handoff.md` §3.8）。
下表是 2026-10-02 条带首版（GDMA 和 conv 并行化之前）的实测，绝对值已过时，
只用来看各分辨率之间的相对快慢（test.ppm，三幅图都回传）：

## 处理模式（7 个）与阈值

「处理」下拉框有 7 项：

| 模式 | 在 PL 里？ | 说明 |
| --- | --- | --- |
| 0 灰度归一化 | ✅ | 按整帧 min/max 拉伸 |
| 1 阈值分割 | ✅ | `gray >= 阈值` 取 255，否则 0 |
| 2 边缘增强 | ✅ | Sobel 梯度幅度 |
| 3 伪彩色映射 | ✅ | jet 彩虹表 |
| 4 组合 | ✅ | 先归一化再查 jet |
| 5 原图直通 | ❌ | PS 直接把收到的原图回传，不碰 PL |
| **6 边缘叠加** | **❌（PS 组合）** | 板子让 PL 跑模式 2 拿边缘图，再把"边缘 >= 阈值"的像素在**原图**上画成**白色** |

模式 6 是 2026-10-02 加的：它只是把已有的两张图叠起来（和 AI 掩膜叠加同一套做法），
原图 PS 手里本来就有，所以**不用改 RTL、不用重出比特流**，只多花一趟 PL 往返
（实测 57.7 ms，与模式 2 的 57.0 ms 相当）。

## 阈值分割的可调门限（+ 自动预设）

左侧参数栏「PL 预处理」里的**门限**：输入框 + 滑块（0..255）+「Otsu」按钮（只在模式 1 / 6 可调）。
它在**每一帧的控制头里**发给板子（v4 控制头），所以换图/换阈值都不用重启板端服务。

阈值的含义**随模式变**（标签会跟着改）：

| 模式 | 阈值是什么 | 自动预设怎么算 |
| --- | --- | --- |
| **1 阈值分割** | 灰度门限 | Otsu 大津法（先自动定"灰度最小值"剔掉背景，见下） |
| **6 边缘叠加** | 边缘门限（Sobel 幅度） | Sobel 幅度的 **92 分位**（≈8% 的像素画白），下限 24 |
| 其它模式 | 用不到 | 自动按钮算的仍是模式 1 的值 |

> 边缘幅度直方图极度偏向 0（大多数像素是平坦区），Otsu 会被压得很低、画得满屏都是边，
> 所以模式 6 改用分位数——"让大约 8% 的像素判成边缘"，视觉上干净可控。
> 实测 `test.ppm` 上自动给 42，板子画白 8.5% 的像素；PC 端 Sobel 与板子 Sobel
> **阈值判决一致 100.0%**（逐值相同 99.2%）。

**载入图片时会自动算一个推荐值**，用的灰度与 PL 完全一致
（`(77R+150G+29B)>>8`），所以算出来的就是"板子上参与比较的那个灰度"上的门限。

### 算的时候会自动定一个"灰度最小值"，把背景剔掉

灰度为 **0 或 255** 的纯黑/纯白像素一律不计入直方图（图像黑边、过曝白块、拼图留白）；
**再自动定一个灰度下限**，低于它的也当背景剔掉——它们会把 Otsu 拽向"背景 vs 内容"
而不是"内容内部的明暗分界"。

下限不是拍脑袋定的，规则是**在暗半区找第一个"合格的谷"**：

| 判据 | 为什么 |
| --- | --- |
| ① 是局部极小 | 谷才可能是两类之间的分界 |
| ② 左侧暗区 ≥ 全图 5% | 挡掉"一圈细黑边"那种假谷 |
| ③ 谷深 ≤ 两侧峰较小者的 30% | 挡掉平坦直方图（渐变图） |
| ④ **暗区要贴在图像边框上**（≥30% 边框像素是暗的） | 背景总在边上；画面正中的深色物体不该被当背景剔掉 |

**为什么要 ②**：眼底图的暗端不止一个结构——"细黑边(0-3) → 谷(~8) →
深色背景环(16-31) → 深谷(~35) → 内容(48+)"。只看第一个谷会切在 8（只削 3.7%），
②把 8 筛掉之后才轮到 35（正好是背景环的右沿，削 26%）。

这一切都只影响**挑阈值所用的统计**；板子仍然对**全部**像素应用这个阈值，
所以提示里的占比是按全图算的，和板子回图对得上。排除得太狠（剩下不到 1/4）时
会**自动退回全量**（黑白的棋盘/二值图）。命令行可以用 `--gray-min N` 手动指定（0 = 不排）。

实测效果：

| 图 | 自动下限 | 一级 Otsu | 说明 |
| --- | --- | --- | --- |
| `test.ppm`（眼底） | **35**（削 26%） | **99** | 不排背景时是 71 → 整盘全白无血管；排掉后血管显形 |
| `test_blackborder.ppm`（纯黑圆窗） | 2 | **101** | 不排背景时是 54 → 整盘全白 |
| `bars` / `checker` / `gradient` | 2 / 0 / 0 | 79 / 0 / 126 | 合成图不乱切（渐变图下限=0） |
| 居中深色物体 | **0** | — | 判据④生效，不会被误当背景 |

提示里会给**两个值**（都是同一张直方图上跑 Otsu，第二级几乎不花时间）：

| | 含义 | test.ppm | test_blackborder.ppm |
| --- | --- | --- | --- |
| **一级（背景/物体）** | 类间方差最大的门限 | 99 | 101 |
| **二级（物体内部）** | 把一级以下清零后再跑一次 | 129（血管） | 131 |

预设填的是一级；想直接看血管就拖到二级那个值，或者自己在输入框里敲。
实测（`test.ppm`，mode 1）纵向扫了一遍：

| 阈值 | 白像素 | 观感 |
| --- | --- | --- |
| 40 | 191757 (73.1%) | 几乎全白 |
| 71（**旧**的自动值，不排背景） | 163773 (62.5%) | 黑边 vs 眼底盘，**无血管** |
| **99（现在的自动值）** | — | **血管显形** |
| 100 | 111859 (42.7%) | 同上 |
| 160 | 4887 (1.9%) | 只剩最亮的部分 |
| 200 | 0 (0.0%) | 全黑 |

> 阈值只对**模式 1** 有效。**模式 3（伪彩映射）在 PL 里是 `jet[gray]` 直接查表，
> 没有阈值参数**——要给它加"色带窗口"得改 RTL 重出比特流，目前没做。
> 模式 0（归一化）和模式 4（组合）自动按本帧 min/max 拉伸，也不需要手调。

⚠ 判据是 `gray >= 阈值` 为**白**，所以"黑"是 `gray < 阈值`——算占比时别把
`== 阈值` 那个桶算进黑里（这里踩过一次，差 1421 个像素）。

一键自检（不开界面）：

```
run.bat --image test.ppm --selftest out.png --flags proc,mask,overlay,stats
```

它会自动发一帧、把右图存成 `out.png`、打印收到哪几幅和 AI 统计，然后退出。

## 协议（与板端 `image_proto.h` 完全一致）

512×512 RGB888，切成 512 个**行包**，每包一行像素：

| 偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 2 | `row` 行号 0..511（小端） |
| 2 | 2 | `length` 固定 1536（小端） |
| 4 | 2 | `crc16` CRC-16/CCITT-FALSE，对后面 1536 字节算（小端） |
| 6 | 1536 | 该行像素，序 R,G,B |

单包 1542 字节；上行 512 包 = 789 504 字节，下行同理。

### 控制头（整幅字节流最前面）

板子**先读 2 字节 magic 再决定读几字节**，所以新旧客户端都能用：

| 版本 | 长度 | 布局 |
| --- | --- | --- |
| v2（旧） | 4 B | `magic=0x4D43` + `mode(u16)` |
| v3 | 8 B | `magic=0x4D44` + `mode` + `flags` + `aiparam` |
| v4（默认） | 12 B | `magic=0x4D45` + `mode` + `flags` + `aiparam` + **`thr`** + 保留 |

`flags` / `aiparam` 的含义见上面「回传内容」一节；`thr` 是阈值分割门限。
`imagelink.py --v2` / `--v3` 可以强制发老头，用来验证板端的兼容性。

回给 PC 的仍然是纯图像流（0~3 幅，按 flags 决定），但 `flags` 带 `stats` 时
**最前面会有 64 字节统计块**（magic `'SIA1'`）。

`proto.py` 在导入时会自检：`CRC16("123456789") == 0x29B1`、各字段算术
（1536 / 786 432 / 1542 / 789 504 / 8 字节 v3 头 / 12 字节 v4 头）、
三个 magic 互不相同、`expected_images()` 的顺序、统计块的打包/解包往返、
以及 v4 头里 thr 字段的位置。**改了协议常量而忘了同步，这里会立刻报出来。**

## 计时口径

```
t0 ──开始发送──► t1 ──发完──► 等板子处理并回传 ──► t2 ──收完整幅回图──►
|<------ send_ms ------>|<------- reply_ms ------->|
|<------------------ total_ms --------------------->|
```

界面上大字显示的是 **total_ms（往返总耗时）**；下面一行是小字拆分，
用来分辨"到底是网络慢还是板子慢"。

### 性能（2026-09-29 优化，往返 1250 ms → **27 ms**）

| 阶段 | 往返 | 关键改动 |
| --- | --- | --- |
| 初始 | 1250 ms | — |
| ① | **114 ms** | PC 端 CRC 换成 `binascii.crc_hqx`（C 实现，快 500 倍）；整帧一次收发 |
| ② | 40 ms | 板端 CRC 改查表；回发整帧一次发 |
| ③ | **27 ms** | 连接复用（不再每帧重连）；整帧大块读；回发复用行 CRC |

其中最反直觉的一条：**最大的一刀在 PC 端而不是板子**——纯 Python 的逐位 CRC
一帧就要 621 ms，收发各算一遍就吃掉了 1250 ms 里的 1220 ms。

详细分析和板端耗时细分见 [`../tcp_image_rx/docs/design_notes.md`](../tcp_image_rx/docs/design_notes.md) 第 12 节。

> 想真正"跑满千兆"要注意：链路上已经是 940 Mbit/s（线速），但**锁步式一问一答**
> 每帧都要等一个来回，压不到线速。要打满带宽得改成流水线形态。

过程中踩到并修掉的两个坑（都写在注释里了）：

1. **tkinter 起不来**：这台机器上一个 Tcl 版本冲突（`have 8.6.14, need exactly 8.6.13`）。
   原因是启动时继承了别处的 `TCL_LIBRARY`。`run.bat` 里已经把
   `TCL_LIBRARY`/`TK_LIBRARY` 钉到这个 Python **自带**的 tcl/tk 上。
2. **板端 `--echo` 会崩**：`send()` 不能对着 `/dev/mem` 映射区读数据，
   内核会直接 oops。改成从**暂存区**发就好了。详见 `../tcp_image_rx/docs/design_notes.md` 4.4。
