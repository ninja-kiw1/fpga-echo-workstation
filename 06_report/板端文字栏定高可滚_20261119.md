# 板端文字栏定高可滚（2026-11-19）

**一句话**：板端 GTK 兼容层的 `Text`（就是界面上那些只读文字栏）**自然高度跟着全文走**，
`height=N` 只当最小值用 —— 内容一长框就自己长高，窗口跟着从 991 长到 1356，内容一路铺到页面底部；
框又正好长到装下全文，`yview` 永远是 (0.0, 1.0)，右边那条滚动条自然拖不动。
修法是给 Text 换一个**自然高度钉死**的 `ScrolledWindow`（重写 `do_get_preferred_height`），
一行代码的差别，框恒等于 `height` 指定的高度，多出来的内容交给滚动条。

- 板上落点：`/data/ws2026/shim/tkinter/_widgets.py`（md5 `4a5bf3cf…`，
  改前 `9da599f4…` 备份成 `_widgets.py.bak_tb20261119`）

## 现象（改前，板上实测）

| 场景 | 改前 | 改后 |
| --- | --- | --- |
| `height=4` 的框塞 20 行 | 框高 **320 px**（4 行应是 64） | **64 px** |
| 主界面「提示方向」塞 20 行 | 窗口 **991 → 1356**（长高 365 px） | **991 不变** |
| 该框的滚动范围 `yview()` | **(0.0, 1.0)** —— 没得滚 | **(0.0, 0.2)** —— 可滚 |
| 「提示方向」框 1639 字 | 框高 640 px（铺到底部） | 64 px，`adj upper=960 / page=64`，`yview("moveto", 0.5)` 生效 |

## 根因

兼容层的 `Text._build()` 用 `Gtk.ScrolledWindow` 包 `Gtk.TextView`，`height=N` 时设了
`set_min_content_height` / `set_max_content_height` / `set_propagate_natural_height(True)`，
以为能把自然高度钳住。**在板上 GTK 3.22.30 实测六种组合全是 340 px（= 全文高度）**：

```
AUTOMATIC min=max=64 prop=False    natural=340
AUTOMATIC min=max=64 prop=True     natural=340
AUTOMATIC max=64 only prop=False   natural=340
NEVER     min=max=64 prop=False    natural=340
（带 set_size_request(-1,64) 时"分配"是 64，但"自然高度"仍是 340）
```

也就是说：`min/max_content_height` 对「我到底要多高」完全不起作用，父容器（兼容层的 pack/grid 宿主 Box）
按自然高度分配 → 框被撑高。框一高，内容就装得下，滚动条自然没得滚。

## 修法

给 Text 用一个固定高度的 ScrolledWindow：

```python
class _FixedScrolled(Gtk.ScrolledWindow):
    def do_get_preferred_height(self):
        return (self._fixed_h, self._fixed_h) if self._fixed_h > 0 else Gtk.ScrolledWindow.do_get_preferred_height(self)

    def do_get_preferred_height_for_width(self, width):
        return (self._fixed_h, self._fixed_h) if self._fixed_h > 0 else Gtk.ScrolledWindow.do_get_preferred_height_for_width(self, width)
```

`height` 选项里把 `self._sw._fixed_h = px` 设上再 `queue_resize()`。滚动仍然走**原来那条路**：
`uistyle.text_box` 在右侧摆一条 `ttk.Scrollbar`，它与 TextView 的 `vadjustment` **共用同一个对象**
（兼容层 `ttk.Scrollbar` 的特性），所以缩略条位置、拖动、`yview("moveto")` 全都自动同步，不用改应用代码。
