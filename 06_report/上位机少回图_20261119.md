# 上位机「少回图」——板端算完到界面显示，回传 3.15 MB → 0.79 MB

**日期**：2026-11-19　**改动范围**：只改上位机（`07_ui/workstation.py` 与 `01_src/ui/workstation.py` 两份同样内容），
**不动板端、不动比特流、不动协议**。搜索 `WS_OPT_V2` 能看到每一处。

---

## 1. 这一刀切的是哪一段

用户口径：**PS/PL 运算完成 → 上位机显示出这一帧**。这一段里板端已经算完，剩下的事只有三件：
把结果图传回来、上位机解包、画到画布上。

实测（同一块板、同一张 512 图、同一份服务端 v5.27，`04_verify/verify_noimg.py`）：

| 环节 | 实测 |
| --- | ---: |
| 板端整网（PL+搬运） | ≈ 285 ms |
| **回传**（按界面勾选 1~4 幅图，每幅 789 504 B） | **49 ~ 165 ms** |
| 上位机解包 + 组图 + 画布 | ≈ 3 ~ 10 ms |

也就是说：**这一段里唯一值得动的就是回传的字节数**。而板端回的东西，有一半是上位机自己就能算出来的。

## 2. 两个实测结论（这次优化的全部依据）

`04_verify/verify_noimg.py` 对 6 张真实 512 图逐字节核对：

1. **板端回的「预处理图」就是上位机刚发出去的那张原图**。
   界面固定走 mode 5（原图直通），md5 完全相同 —— 786 432 B 原样绕了一圈回来。
2. **「掩膜图」和「叠加图」是纯函数**：`mask_rgb(plane, thr)` / `overlay_rgb(底图, plane, thr)`，
   与板端回传的那两幅**逐字节相同**（这套等价性本来就有：`_load_logits` 里那条
   「与板端逐字节一致 ✓」自检一直在跑同一件事）。

所以只要板端把 **logit 一幅**传回来，其余三幅上位机自己生成即可。而且 logit 本来就要传
（掩膜、叠加、热力图、拖门限重算全靠它）。

## 3. 改了什么（7 处，全在 `workstation.py`）

| # | 位置 | 改动 |
| --- | --- | --- |
| 1 | `App._fast_flags`（新增） | 决定本帧走不走「少回图」，并改写 flags |
| 2 | `App._on_send` | 记下本帧真正发出去的字节；调 `_fast_flags` |
| 3 | `App._on_result` | 把发出去的原图补回 `images["proc"]`，下游看到的结构与老口径完全一样 |
| 4 | `App.__init__` | 新增 `inflight_image` / `fast_noimg` 两个字段 |
| 5 | `App._render_right` | 右图来源提示：`本地生成（板端只回 logit 一幅）` |
| 6 | `SeqWindow._send`（心超单步/点击纠错） | 丢掉 `FLAG_ECHO_MASK` —— 掩膜本来就是本地 `prior_from_plane` 算的，板端那幅只用来打「与板端一致」的标记 |
| 7 | `SeqWindow._show_step` | 没有板端掩膜可对比时，状态栏写「掩膜本地生成（板端只回 logit）」 |

新口径下发的 flags：`(原 flags 去掉 PROC/MASK/OVER) | LOGIT | STATS`。

**四种情况自动退回老口径**（`_fast_flags` 里逐条判断）：

- **ROI 帧**（`roi is not None`）：底图与裁剪窗口相关，不碰；
- **老板端**（统计块 version < 2，不认 b5）：没有 logit 图可拿；
- **没勾掩膜/叠加**（只回预处理图）：本来就只回一幅，没什么可省；
- **点击纠错帧**（`inter is not None` 或纠错会话进行中）：历史栈里要存当时的原图。

环境变量 `WS_NO_FASTIMG=1` 可整体关掉，回到 2026-11-19 之前的行为。

## 4. 结果（上板实测，同一张图、每档 5 次取中位）

`04_verify/verify_noimg.py` 第 2 步，界面四种「回传内容」勾选组合：

| 回传内容（界面勾选） | 改前 | 改后 | 省 | 改后回传字节 |
| --- | ---: | ---: | ---: | ---: |
| 只「预处理图」 | 413.4 ms | 405.3 ms | 8.0 ms | 789 504 B（不生效，本来就一幅） |
| 预处理 + 叠加（默认 AI） | 465.9 ms | **416.4 ms** | **49.6 ms（−10.6%）** | 789 504 B |
| 预处理 + 叠加 + 掩膜 | 518.5 ms | **423.7 ms** | **94.8 ms（−18.3%）** | 789 504 B |
| 预处理 + 叠加 + 掩膜 + 置信度 | 581.1 ms | **430.8 ms** | **150.3 ms（−25.9%）** | 789 504 B |

心超那条「单步 / 点击纠错」通路（原来是「掩膜 + logit」两幅）：

| 通路 | 改前 | 改后 | 省 |
| --- | ---: | ---: | ---: |
| 心超单步（序列跟踪，512） | 469.0 ms | **404.0 ms** | **64.9 ms（−13.8%）** |

> 这条链路里 1 幅 789 504 B 的图实测约 49~55 ms（≈ 14~16 MB/s），所以每少回一幅就是这么多。

## 6. 保留意见

- **logit 那幅本身还是 786 432 B**：板端把它编成 `R=G=B=logit+128` 的 24 位图，一个像素 3 字节只装 1 字节信息。
  要再省 2/3（≈ −32 ms），得在板端加一条「紧凑 logit」回传（n 字节 int8 + CRC16，与紧凑帧的
  `FLAG_C_LOGIT` 同一套），**这需要改服务端并重启**，本次没做。
- 「与板端逐字节一致 ✓」这个标记在心超单步通路里不再显示（不再收板端掩膜），改成
  「掩膜本地生成（板端只回 logit）」。等价性已由上面第 1 步一次性钉死。
- 本次没动心超**整段视频**（mode 2 / 现场模式）：那条路回的是位掩膜（112×112/8 = 1 568 B/帧），
  传输本来就只有几百微秒，省不出东西。
- 沙箱没有 tkinter，界面本身没有真开起来跑过；改动都是 flags 与数据结构层面，
  像素等价性用上面两个脚本离线钉死。
