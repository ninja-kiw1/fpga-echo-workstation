# 标尺定标没进证据报告（2026-11-18 修）

## 现象

在关键帧 / 现场模式里点了「标尺定标…」（按钮已经变成「标尺 0.98 mm/像素」），导出的《心超分析证据报告》里仍然写着

> 右房：收缩末面积 / 左室舒张末面积 0.38（2 / 2 拍通过位置检查；**无像素间距，只给比值**）

而且报告通篇找不到标尺数值，看起来像"标尺没生效"。

## 根因

标尺定标的结果只存在一个地方：`heartapp` 主窗口的 `calib`（`原始录屏文件名 -> mm/像素`），由 `heartview._spacing()` 换算到 112 尺度使用。它只被两处消费：界面上的「标尺 x mm/像素」按钮文字、以及「送到快照测量」。**报告这条路完全没接**：

- `heartview._report()` 组装给 `write_report` 的 info 里没有 spacing；
- `echo_ws.heart_text()` 里"无像素间距，只给比值"是硬编码字符串，不判断有没有标尺；
- `write_report` 的「计算过程」一节也没有标尺一项。

所以不是定标没成功，是报告从来没读过它。

## 口径（写清楚，别以后又被当成 bug）

1. **面积是几何换算，不是机器自带的面积测量**：报告与原文字里都注明了"按屏幕标尺换算"。屏幕标尺定标本来的精度就取决于手点两个深度刻度，误差直接进面积（面积是长度的平方）。
2. **挑拍条件必须与板端比值同源**：板端 `n_rv` 要 `rv_ok_ed && rv_ok_es && lv_ed>0`，`n_ra` 要 `ra_ok && lv_ed>0`（`ok` 位里已含触边判定 `cardiac_ext.c:304`）。PS 侧照抄同一条件，否则"面积 7.5 cm²"和"比值 0.50"不是同一批拍。
3. **没定标就不猜**：spacing 为 None / 0 / 非数字时一律退回"只给比值"，并在报告「计算过程」里明确写"未定标"，让读报告的人知道为什么没有 cm²。
4. EF、RV 面积变化分数、节段运动都不受标尺影响（比值 / 无量纲），报告里也写明了。

## 验证

`07_ui/_verify_report_scale.py`（离线自检，不连板子，`python _verify_report_scale.py`）：

- 没标尺：`无像素间距，只给比值`，且输出里不出现 `cm²`；
- 标尺 1.00 mm/像素、两拍 RV=500/1000 px²、RA=300/600 px²：算得 7.5 / 4.5 cm²，与手算一致；第三拍（右室触边、面积 9999）被正确排除；
- 标尺传 0 / None / 字符串：退回只给比值；
- `write_report` 端到端：有标尺的报告含「标尺：屏幕深度标尺定标（原始录屏 5.000 mm/像素），112 尺度 1.000 mm/像素」与两组 cm²；没标尺的报告写「标尺：未定标（没有像素间距）」。

**没有做的**：没有上板用真实病例重跑一份报告（需要板子在线、手点一次定标）。逻辑与数值已离线核对，真机口径待下次上板时再看一眼。
