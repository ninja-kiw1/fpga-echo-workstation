# 板端「全心卡片出文字 → 左右两个框向两侧移动」修复（2026-11-19）

**一句话**：这不是界面代码的问题，是**板端 GTK 兼容层算错折行宽度**：`wraplength` 是像素，
它换算成 GTK 的 `max_width_chars` 时按 **8 px/字符** 估，而中文实际约 **16 px/字符** ——
折行标签的自然宽度被放宽近一倍，把所在栏撑宽；body 在窗口里是居中（`sticky="n"`）的，
于是**左栏向左、右栏向右各移 72 px**，同时留下一片没重绘的残留。

修一行换算（`_widgets.py` 的 `Label._chars_for_px`），三栏在分析前后**逐像素不动**。

  改前 `8636ea40…` 备份成 `_widgets.py.bak_wrap20261119`）

## 根因

`shim/tkinter/_widgets.py` 里 `Label` 处理 `wraplength`：

```python
lb.set_max_width_chars(max(8, int(px / 8.0)))     # ← 按西文 8 px/字符估
```

而应用侧的写法是「折行宽度 = 自己分到的宽度 − 4」（`uistyle.label(wrap=True)` 里的 `<Configure>` 绑定）。
两者一凑就成了正反馈：标签自然宽度被放宽 → 栏变宽 → 分到的宽度更大 → 折行宽度更大 → 再放宽。
中文在板上的字宽约 16 px，所以第一轮就直接放宽到约 2 倍，肉眼就是「唰地散开」。

PC 侧不受影响：Windows 上是真 Tk，`wraplength` 本身就是像素、请求宽度永远 ≤ wraplength
（实测：文本 8 字 → 40 字，reqwidth 111 → 292，wraplength 296 封顶，不再涨）。所以**这次只动板端兼容层**，
`07_ui` / `01_src/ui` 一行没改，也就不需要重新生成板端 app。

## 修法

用 Pango 量当前文本的实际字宽再换算字符数（中西文都合适，和文本内容无关，只取比例）：

```python
def _chars_for_px(self, px, text=None):
    s = text or u"国"
    try:
        lay = self._label.create_pango_layout(s)
        w = lay.get_pixel_size()[0]
        if w > 0:
            return max(8, int(round(px * len(s) / float(w))))
    except Exception:
        pass
    return max(8, int(px / 8.0))        # 拿不到 Pango 就退回旧估法
```

顺带的好处：板上**所有** `wrap=True` 的标签（复查提示、质量灯原因、提示方向、全心文字……）
都从「按 8 px/字估」改成按真实字宽，以前那些「文字一长整栏就变宽」的隐患一并没了。
