# 板端上位机同步（PC 版 → 板端版）· 2026-11-19

## 一句话

板端 `/data/ws2026/app` 原来那份上位机是 11-17 从单文件版分叉出来的，落后 PC（`2026pld/07_ui`）
整整一天的功能。这次**以 PC 版为唯一来源、用脚本重新生成板端版**并上板：像素标尺 / 自动定标 /
原生分辨率预览 / 双平面病例 / 少回图 / 输出文字固定宽度等全部到位，11-19 的拖动提速层原样保留；
右心「触边判定」按用户要求 **PC 与板端一起关掉**。

## 一、PC 侧改了什么（`2026pld/07_ui`）

右心「触边判定」整体关闭：

| 位置 | 改动 |
| --- | --- |
| `heart_block()` | HC01 末 8 字节 `border_px` 固定写 `BORDER_PX_OFF = 0.0`，不再读配置 |
| 常量 | 删 `BORDER_PX / BORDER_PX_LABELS / BORDER_PX_VALUE`，留一句 `BORDER_PX_OFF = 0.0` |
| 界面 | 「全心」卡片里的档位下拉、说明文字、`var_border` / `border_px` / `_border_label()` / `_border_changed()` 全删 |
| `_heart_cfg()` | 不再往 `right_heart` 里塞 `border_px`，原样返回配置 |
| `echo_heart_config.json` | `"border_px": 0`（值已不起作用，只为读起来一致） |

验证：`04_verify/verify_pc_border.py` —— 界面能建、控件树里没有「触边」字样、
即使配置写 3.0 出来的 HC01 末 8 字节仍是 0（8/8 PASS）。

## 二、板端版怎么来的（`03_build/make_board_ws.py`）

**PC 版是唯一来源**，板端版 = 脚本输出。脚本里每一步都带锚点断言（锚点数量不对就报错退出），
所以 PC 版以后改了形状，这里会立刻炸出来，不会静默漏掉某一层适配。

```
python3 03_build/make_board_ws.py  <PC 目录>  <输出目录>
#   PC 目录：含 workstation.py / echo_ws.py / proto.py（即 07_ui）
#   输出目录：板端 app/ 要放的三份文件
```

生成的板端适配共五块：

1. **术语**（11-17 定的口径）：板端→引擎、板上/板子→设备、服务端→引擎、回传→输出、
   发送→处理、上传→送入、上位机→本机、板卡地址→系统名。
2. **不暴露地址 / 端口**：顶栏与眼底页的地址、端口输入框删掉（`var_host/var_port` 留着走内部）；
   `DEFAULT_HOST` 两处改 `127.0.0.1`；`imagelink._cli` 默认地址改 `127.0.0.1`；
   `route_hint()` 换成单机版（一律返回空串，不再诊断网段 / 代理）。
3. **右心触边判定**：沿用上面 PC 侧的关闭状态（板端同样固定 0）。
4. **拖动缓存层（11-18 一轮 / 11-19 二轮）重新挂上去**——这是 PC 版没有、只在板端有意义的部分：
   `_vcache`/`_vorder`/`_vprep`/`_vlock`/`_vgen`、`_vclear/_vprep_build/_vprep_get/_vprefetch/
   _vwarm_photos/_frame_photo/_render_frame/_render_deferred/_vsettle_later`、
   `_draw_cursor(only=)`、ED/ES 角标画进图里（走 `_canvas` 单图快路）、
   时间线两条提示文案缩短（板上画布只有 392 px）、`_apply_view` 变尺寸时整批作废。
5. **本次新增的一处**：拖动中**先不挪播放进度条**（`_scale_pending`），等真正出图那一帧再一起挪 ——
   拖动时事件比出图密得多，进度条每动一次都要让 GTK 重排一遍（板上实测一次 ~40 ms）。

`echo_ws.py` 同样由脚本生成：PC 内容 + 板端的 `_edge()`（112 网格判边再放大，448² 上少做四次布尔与）
与 `contour_rgb()`（去掉 `np.repeat`，板上 numpy 1.13 上那一步 21.9 ms）两份提速实现。
`proto.py` 只做术语改写（PC 版是 v9 / 带 112 任意边长，比板上那份 v8 新）。

`04_verify/verify_cache.py`：14 项全 PASS —— 建界面、帧尺寸、**逐像素与"老 `_goto` 合成"一致

`_vprefetch` / `_vwarm_photos` 能填满缓存、HC01 末 8 字节 = 0。

### 板上（`/tmp/ws_stage` 暂存区，先不碰正在跑的那份）

| 检查 | 结果 |
| --- | --- |
| `board/smoke.py` | 主窗口 + 快照/关键帧/现场三模式 + 平台扩展全建起来（`SMOKE_DONE`） |
| `board/func.py` | 引擎 v5.28、真发一帧 385.3 ms；扫 412 个文本变量，**没有地址 / 板子字样**（`FUNC_OK`） |
| `04_verify/verify_echo.py` | `demo_a4c.y8` 99 帧 636×422 端到端：载入 1.7 s、分析 2.3 s、**EF 38.1%、掩膜 99/99**、右心出数且 `n_border=0`、拖动 60 事件 → 1 次出图、截图见下 |
| 截图 | 原生预览 1:1（636×422）+ 红色轮廓、**自动定标"1.24 mm/像素"**、像素标尺行、容积曲线 6 拍、心率 112 次/分（近 5 拍）、全心卡片 RV/LV 0.34 / RA/LV 0.27、PL 推理 18.1 ms |

### 拖动耗时（`04_verify/probe_render.py`，同一台板、同一段视频、新旧交替跑两轮，取各轮数值）

| 项 | 旧板端版 | 同步后 |
| --- | --- | --- |
| 换一帧的纯计算（缓存命中） | 0.8 ms | 0.9 ms |
| 60 个拖动事件 → 真正出图次数 | 1 次（0.18 ms/事件） | 1 次（0.18 ms/事件） |
| 拖播放进度条（每步含刷新） | 7.3 / 7.4 ms | 8.9 / 9.3 ms |
| 点/拖容积曲线（`_curve_click` 真入口） | 54.3 / 55.5 ms | 63.4 / 67.5 ms |
| 模拟快速拖动（60 事件 / 10 次刷新） | 7.1 / 7.1 ms/事件 | 6.0 / 8.2 ms/事件 |

**怎么读这张表**：这块板的成本大头从来不是我们的代码，而是 GTK 刷新 —— 同一个探针里
「什么都不改只 `update_idletasks`」一次能到 0.9 ms 也能到 95 ms（跟桌面上还有没有别的窗口重绘有关），
单次绝对值波动很大，所以上面每项都跑了多轮、新旧交替。两版**纯计算一致、事件合并一致**，
进度条拖动与快速拖动都在同一水平（差 1~2 ms，落在噪声里）；只有「点曲线」这一项稳定多 10 ms 左右，
原因是 `_curve_click` 会回头挪 `ttk.Scale`，兼容层里 `set()` 一次要重排整窗（旧版同样如此，
旧版 54 ms 里约 41 ms 是它，新版界面控件更多所以更贵）。**没有发现哪一项是同步引入的计算量。**

## 五、注意 / 没做

- **开机不自启**（沿用 11-18 口径）；桌面图标「心超工作站」→ `/data/ws2026/board/launch.sh` 不变。
- **双平面病例样例**：板上 `/data/ws2026/app` 没有 `echo/samples`，病例列表会是空的。要演示就把
  PC 的 `07_ui/echo/samples`（19 个文件 14 MB）拷到板上 `app/demo/` 或 `app/echo/samples/`，
  新的搜索逻辑（`echo_samples_roots()`）会自己认出来。
- **右心触边判定**：PC 与板端都固定 0（不查）。板上服务端仍认这个字段，恢复要同时改
  `heart_block()` 和 `_build_middle()` 里的界面。
- **引擎一次只服务一个客户端**：板上界面在跑的时候别再让 PC 上位机发任务（11-19 起不再封 5060 端口）。
- 兼容层（`shim/tkinter/_canvas.py`、`_gtkbase.py`）这次**没动**，还是 11-19 那两份。
