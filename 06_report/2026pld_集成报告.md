# 2026pld：11-13 版 + 112 直跑 + 扇形裁剪

**构建日期**：2026-11-18
**基线**：`PLD_share_lite_20261113`（2026-11-13 那版分享包，服务端 v5.27 heart-only，固件 f150nv）
**加进来的两个特性**：① 心超 **112×112 直跑**（去掉 128 补边）② **扇形裁剪**（P15 口径：三层全裁 + 几何逐帧自标定）
**除此之外没改任何东西** —— 具体"没动什么"见 §4。

> 所有产物按分组放在本目录：`01_src`（源码）、`02_bitstream`（比特流）、`03_build`（构建脚本与日志）、
> `04_verify`（验证脚本与实测）、`05_deploy`（部署脚本）、`06_report`（本文件）。

---

## 1. 一句话

以 f150nv 的 PL 为底，只在 conv kernel 上做了**去 `%3` 取余**和**追加 6 个扇形列区间寄存器**两件事，
重综合出一块新比特流；PS 侧把 112 直跑与 P15 扇形逻辑并进 v5.27 服务端；上位机跟上 112 口径。
**没有任何一项旧功能被改动语义**：`fan_on=0` 时 conv 与本文件原版逐位相同，扇形成像之外的全部模型/分辨率逐位不变。

---

## 2. 为什么要以 f150nv 为底重做，而不是直接拿 P14

11-13 这版服务端启动时要读 `img_proc` 的 VERSION（`0xA0000010`），而 P7 起的比特流（含 P10/P13/P14）
已经把 `img_proc` 整块删掉了 —— 读那个地址是 Synchronous External Abort。所以：

- **不能**"PL 用 P14、服务端用 11-13 版"；
- **也不能**"PL 用 f150nv、服务端换 P14 版"（P14 版会写 conv 的 `0xC0~0xE8`，f150nv 的 conv 里没有这些寄存器）。

唯一自洽的路就是：**在 f150nv 的 conv 上把扇形寄存器补出来**，服务端仍以 11-13 版为底。这样做出来的东西
既保留了 11-13 版的全部行为（含 `img_proc`、`--programs` 程序包、pp 层），又有了 112 与扇形两个特性。

## 3. 具体改了什么

### 3.1 PL：`01_src/PL/src/conv_layer.cpp`（唯一的 PL 源码改动）

| 改动 | 位置 | 说明 |
| --- | --- | --- |
| 去 `%3` 取余 | 3 处 | `ry % 3`、`(prow + 6) % 3` 与两处 `(iy + 6) % 3`（init / 补窗）全部换成递增计数器。原写法被综合成 `srem_32ns_3ns`（36 拍流水除法器），把 STEP_ALL 迭代延迟从 9 拍拖到 44 拍 |
| 扇形寄存器 | 函数末尾追加 6 个参数 | `fan_on / fan_xa0 / fan_xag / fan_xb0 / fan_xbg / fan_y0`，AXI-Lite 偏移 **0x84 / 0x8C / 0x94 / 0x9C / 0xA4 / 0xAC**（已从 `conv_layer_control_s_axi.v` 核过） |
| 每行列区间 | ROWS 循环内 | `x0(y) = xa0 - ((xag*ay)>>8)`、`x1(y) = xb0 + ((xbg*ay)>>8)`；区间用**累加器**推进（行内只有加法/移位，第一版每行一次乘法把 WNS 打到 −0.180） |
| 五个裁剪点 | 滑窗初始化 / nsteps / wcol0,st_x0 / 存回闸门 / MERGE 回写+预取 | 全部按 `[wx0, wx1)` 收窄；`fan_on == 0` 时这些式子退化成原值 |

**没有引入** P10 的静态移位、P13 的计数器窄化、T1/T3 的位宽裁剪 —— 那几刀不在这次需求里。

### 3.2 PS：板端服务端

| 文件 | 改动 |
| --- | --- |
| `job_echo.c` | 112 直跑：`EPAD 8→0`、`ES 128→112`，新增 `E128 128` 给 CAMUS/F1 链；4 处 `job_unet(model,2,…)` → `job_unet_hw(model,ES,ES,…)` |
| `job.c` / `job.h` | 新增 `job_unet_hw(model,h,w,…)`（走 `unet_set_size`）；`job_unet` 里显式 `unet_set_fan(0)`，`job_unet_hw` 里按模型开关扇形 |
| `tcp_image_server.c` | 紧凑帧尺寸校验放宽到「8 的倍数、≤512」；`by_size` 时走 `unet_set_size`；`handle_v6c` 里按「扇形模型 + 任意边长」开关扇形 |
| `ai_view.h` | `AI_STAT_VERSION 8→9`（v9 = 认任意 8 的倍数边长） |
| `unet_ai.c` / `unet_ai.h` | 新增扇形几何状态与 `fan_pad / fan_set_fixed / fan_calib / fan_params`、`g_fan_d[]` 全流程膨胀表、`unet_set_fan()`、`unet_model_is_sector()`；`unet_run` 里逐帧标定；节点循环里算区间、每条带写 6 个寄存器 |

`unet_ai.c` 里扇形那一段是**原样搬** P15 的实现（几何余量按层给、逐帧从图像黑边最小二乘标定、标定失败整帧不裁），
只把寄存器偏移换成上面这套。

## 4. 明确"没动"的清单（兼容性承诺）

- 固件里除 conv 以外的三个 IP：`eltwise_layer`、`pp_layer`、`img_proc_axil` —— 用的是 f150nv 原来那两个 IP 仓库，**一字未改**
- BD 结构、PS 预设、时钟（MMCM 150 MHz）、地址映射（`0xA0000000/0xA0010000/0xA0020000/0xA0030000/0xB0000000`）、数据互联 9 个从口 —— 原脚本机械改路径，逻辑一行没动
- 服务端：眼底（模型 0）、皮肤（1）、CT、程序包（`progpkg`）、pp 后处理、live 通路、`jobs`（v7 病例任务）
- 扇形的**默认状态是关闭**：只有「模型 2/3/4/16 + 任意边长档（112 直跑）」才打开；走档位的 512/256/128/64/32 一律关

## 7. 保留意见

1. **绝对性能被 f150nv 基线锁住。** 同一块板、同一份服务端，128 档本版 22.4 ms，而 P13/P14 那套血统是 20.4 ms；
   112 档本版 18.0 ms（扇形关），P13 是 16.2 ms。也就是说这两代 PL 之间还有约 10% 的差距（P10/P13 那几刀
   不在这次需求里）。**两个特性本身的相对增益与 P13→P14 上测到的完全一致**（112 −20%、扇形 −6%），
   但绝对数字比 P14 那版慢。要追平就得把 P10/P13 的优化也搬进 f150nv 的 kernel —— 那属于"其余内容"了。
2. **去 `%3` 在这套 f150nv 结构上没有换来时间收益。** csynth 显示 STEP_ALL 迭代延迟 36 911 → 36 877 拍，
   几乎没变；整片只省了 LUT −2 849 / FF −2 559。P8 报告里"迭代延迟 44 拍 → 9 拍"的结论是在 P6pf2 血统上成立的，
   f150nv 这一版的 `%3` 本来就不在流水线关键路径上（关键路径是 BRAM 访问）。**收益是资源，不是速度。**
3. **扇形的边界差比 P15 原报告略大。** P15 在 112/m16 真实帧上是 21/6640 且 |Δ| ≤ 4；本版是 66/6640、
   |Δ| 最大 9，全部落在扇形边界 ≤3 px 内，**掩膜（logit ≥ 1）一位没变**。如果以后换探头/换张角，
   建议重新核一遍这条边界差。
4. **CLB 已经 97.65%**（f150nv 原本是 99.23%），虽然比原来松一点，但再加逻辑的空间很小。
5. **快照（CAMUS）那条链仍是 128**，这次没动（`sequence.py`、17/18 号程序包、`echo_lv`）。这是照 112 包的
   口径来的（CAMUS/F1 原生 128 帧），不是漏改。
6. **这次没跑的**：17 个内置模型的完整回归、眼底/皮肤/CT 通路、现场模式（采集卡）、Simpson/应变。
   **整病例 `echo_ef` 与点击纠错这次跑通了**（见 §5.3 的端到端表，132 帧 / 140 帧两段都在 112 上跑完、EF 与质量灯都出来了）。
   上板验证覆盖的是：6 个程序包自检、4 个模型的逐位比对、112/128 两条通路的逐位与计时、整病例与点击纠错端到端、上位机连板。
7. **板上只删了"程序"**：`/data` 下旧的服务端/工作区/备份全删了，`/root/echo_src` 的演示视频保留（现场模式要用）。
   系统与内核没动，也没有重刷 SD 卡。
