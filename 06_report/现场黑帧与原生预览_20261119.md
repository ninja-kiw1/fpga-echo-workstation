# 现场模式：黑帧修复 + 原画质预览 + 自动/手动定标（2026-11-19）

这一版改了板端服务端（**v5.27 → v5.28**）和上位机，四件事：

| 用户看到的变化 | 怎么做的 |
| --- | --- |
| 现场模式开头不再有纯黑帧 | 板端在采集线程里把采集卡开流头那 85~108 帧纯黑**直接丢掉**，不计数、不进找方块、不进推理、不回传 |
| 现场预览是原画质 | 板上每个 live 块多回一块**裁剪方块的原生帧**（480×480 灰度），上位机 1:1 画，不再是 112 放大 |
| 现场也能自动定标 | 板上另回 **3 块整屏**（第 0/30/60 帧），上位机各读一次深度刻度、三者相差 ≤10% 才取中位 |
| 三个模式都能手动定标 | 关键帧 / 现场 / 快照 各一个「标尺…」：点两个深度刻度 + 填这两点之间几厘米（**默认 5 cm，可改**） |

## 用法

* **自动**：载入录屏（关键帧）或点「开始采集」（现场）后自动跑，工具条那行显示
  `标尺 x.xx mm/像素（自动）`；现场要等板上回的那 3 块整屏（开流后约 4 s）。
* **手动**：点视频卡头的「标尺…」→ 在弹出的整屏图上点两个刻度 → 「两点之间」填 5（或改），确定。
  那行字变成 `标尺 x.xx mm/像素（手动）`，**自动结果不会再覆盖它**。
* **重来**：点「自动」清掉这一段（含手动）的定标重新读一遍。
* 快照模式的「标尺…」在「双平面测量」卡片里，覆盖 CAMUS 文件里的 `spacing_mm`，面积 / 容积 / Simpson 都跟着用
  （只影响本次载入，不动文件）。

## 现场模式的两个数（板端实测，采集卡 USB3 5000M）

* 开头丢掉的黑帧：**56 帧**（`stream.black_skipped`），第一块 live 的 112 帧 max = 249（真画面）；
  改前是 max = 0 的纯黑，而且黑帧让「找运动方块」失败、crop 退回整屏 640×480。
* 延迟（采到 → 掩膜 + 容积）：**P50 27.1 ms / P99 1832 ms**（P99 是前 50 帧找方块的窗口，改前 P50 23.8 / P99 2070）。
  原生帧让每帧 resize 从 2.77 ms 涨到 5.31 ms、链路多 6.9 MB/s（30 fps）。
* 自动定标三次读数：0.347 / 0.347 / 0.337 mm/px → 中位 **0.347**（工具栏按 112 尺度显示 1.49 mm/像素）。

## 开关

| 环境变量 | 默认 | 作用 |
| --- | --- | --- |
| `WS_LIVE_NATIVE` | `1` | 设 0 就不请求原生帧，现场预览回到 112 放大（服务端还是 v5.28，黑帧照样丢） |
| `WS_LIVE_NATIVE_MB` | `320` | 原生帧的内存预算；20 s×60 fps×480²＝276 MB 装得下，超了自动按步长抽稀 |

老服务端（v5.27）也能用：`caps` 里没有 `live_native`，上位机自动退回 112 预览、不做整屏定标，其余不变。

## 已知限制

* 板端工作站 `/data/ws2026` 那份是移植版，这次**没跟着换**：板子自己那套界面只有黑帧修复生效（在服务端），
  预览仍是 112 放大、也没有手动定标。
* 板端界面上 60 fps 长跑时约两成帧没有原生帧（客户端画 480² 一帧 100 ms → 反压 → 板端 64 帧环形缓冲被覆盖），
  那几帧退回 112 放大；PC 上没有这个问题。
* `.y8` 回放路径没跑回归（黑帧跳过只对 v4l2 生效，112 帧通路一个字节没动）。
* 定标只认"刻度等距"、不认数字，遇到 0.5 cm 小刻度的机型会差 2×。
