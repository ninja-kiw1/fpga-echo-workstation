# 部分 C：眼底大图无缝分块 + 框选放大（HRF）

日期 2026-10-18。服务端 **v5.20** `9c2ede7f…`（回滚 → v5.19 `bc386abc…`），固件 f150 不变，模型 0 权重一字未改。
措辞：血管分割与形态指标是**测量辅助**，不作诊断。

## 一句话

同一个固定的 512 PL U-Net 引擎，算任意大小的图、任意框、任意放大倍数：框按 512 自动分块，每块不贴图像边的那几条边各留
24 像素**真实邻域**，只取各块的"自有区"拼回——**结果与"该倍数整幅图一次推理"逐位相同**（不是近似，不是羽化融合）。
界面是"总览 + 框选放大"，原来的 ROI 框选成为 1 倍的特例（同协议、逐位相同）。

相关做法（报告里引用）：U-Net 原文的 overlap-tile 策略（这里做到整数推理逐位一致）；Xilinx VCU / VVAS 的 ROI 流水线
（粗检测 → 映射回原图 → 裁剪 / 缩放 → 精推理）；FPGA 超分 / 图像处理的分块 + 按内容调度；CNN 加速器的循环分块（Zhang FPGA'15）。

## 定义

- **层**：原图按比例 s 缩放（Pillow LANCZOS，与上位机拉伸 512 帧同一种滤波），右 / 下补黑到 8 的倍数（`tile_engine.make_level`）。
- **放大倍数 m**：s = m × 600 / 原图宽。**1 倍 = 原图宽缩到 600**（眼底视野约占图宽 93%，STARE / HRF / DRIVE 都是，≈ 视野宽 560）。
- **块**：≤ 512、起点 4 对齐、尺寸 8 的倍数；一块够用时 = 老 ROI 的裁剪窗口（`proto.roi_crop` / 板端 `ai_view_roi_crop`）；
  否则从 floor8(框起点 − 24) 起每 464 像素一块，最后一块只取需要的长度。规划在 `tcp_image_ui/tile_engine.plan_axis` 和板端 `src/tile_plan.c`，两份逐项相同。
- **自有区**：各块不重叠、正好铺满框；每个自有像素在不贴图像边的方向上离块边 ≥ 24（裁剪边界的影响最深 22，`ai/net/roi_exactness.py`）。
- **视野跳过**：自有区里没有一个亮度 (77R+150G+29B)>>8 > 20 的像素 → 不算（HRF 上这一判据与官方视野掩膜逐像素相同）。
- **上限**：每张图能"重新推理"的最大倍数 = min(模型上限 2.5×, 原图宽 / 600)。层不能比原图大——再大就是把原图插值放大后送进网络，没有新像素。
  超过上限的倍数只给"显示放大（仅插值）"，界面写明。**不做超分。**

（4 倍整幅 24 块跑 20 块，U-Net 5211 → 4988 ms，−4%）；框在视野外时整块不算（一个角落框 50 ms → 1 ms）。

## C2：板上（服务端 v5.20，病例任务 `JOB_TILE = 8`）

- `src/job_tile.c`：层像素来自板上 `/data/hrf/<图>/m<倍数>.lvl`（PC 做好的金字塔，板子 pread 逐行裁剪）或上传的区域；
  每块：PL 上 U-Net（`unet_set_size`）→ 自有区在 **PL pp_layer** 上阈值 + 4 连通计数 + 掩膜位图 → 在 **PL vis_layer** 上叠加（底图 = 层 RGB，血管涂红，
  可选不确定带）；没有 pp / vis 的板子或 `TILE_PS_POST` 时 PS 算同一规格。逐块回一个 "tile" 块（边算边回，界面逐块填），计算顺序可由 PC 给（按总览不确定度）。
  `src/tile_plan.c/.h` 规划；`job.c` 加分发、caps 任务表 `"tile"`、`"server":"v5.20"`；`job_overlay.c` 导出 `job_overlay_compose`；`job.c` 加 `job_unet_account`。
- 金字塔 `c2_pyramid.py build / push`：50 张图（HRF 45 + samples 里的 STARE 5）× 每张图上限以内的层（HRF 1 / 1.5 / 2 / 2.5 倍，STARE 1 / 1.167 倍），
  449 MB 在 `/data/hrf`（板上 sha256 全部核对 `PYRAMID_SHA_OK`），清单 `pyramid/manifest.json` → `tcp_image_ui/tile_pyramid.json`（键 = 原图 RGB 的 sha256）。
- r3（PL 直接从 DDR 经 HP0 读原图做裁剪 / 缩放，§9.75）**没做**：现在 PS 裁剪一块 0.4–2 ms（文件）、PL 推理一块 292 ms，裁剪不是瓶颈；
  接口留好了——`job_tile.c` 的 `src_crop()` 是唯一取像素的地方，换成 PL 从 DDR 读即可，规划和拼接不动。

**耗时**（f150，板上软件计时）：每块 U-Net = **1.10 µs/像素 × 面积 + 3.3 ms**（77 块拟合；512² → 292 ms，与整帧相同）——分块只多 halo，没有别的开销。
视图：HRF 1 倍总览 2 块 **0.30 s**；2 倍整幅 6 块 1.23 s（只回 logit 时任务 1.25 s，开销 2%）；4 倍整幅 20 块 5.0 s；框选放大常见 50–400 ms（1–2 块）。
PL 后处理比 PS 快约 2 倍（2 倍整幅：pp 10.5 ms vs PS 26.7 ms，vis 叠加 24.8 ms vs PS 98.5 ms）。tile 块不压缩（A53 上 zlib 比千兆网发原样慢）。

**上位机**：主窗口的 ROI 框选升级为"框选放大"（`app.py`，备份 `app.py.bak_before_c_20261018`）：侧栏「框选放大」1 倍 = 原来的 ROI（v5 控制头，原有 var_* / 方法名都在，
`verify_board_v4` / `verify_board_v5_ui` 的 ROI 检查照旧过）；> 1 倍时品红框，「发送」= 框映射回原图、打开**大图精查窗口**（`bigwin.py`）：
总览（1 倍，板上分块）+ 不确定度格子 + 编号建议框（视野内不确定像素比最高的 96 像素格）→ 拖框 / 点建议框 → 选倍数 → 在 PL 上按不确定度从高到低逐块重算、逐块填进放大视图；
显示：板上叠加 / 掩膜 / 置信度热图 / 不确定区域 / 原图；「显示放大（仅插值）」单独一个控件；指标行：块数、跳过、halo、有效像素、每块 / 视图耗时、视野内血管密度、
形态指标（`vessel_morph_ref`：骨架长度换算成原图像素、分支、端点、段、迂曲度、分形维数）。界面真板验收 `verify_board_tile_ui.py` → `TILE_UI_BOARD_PASS`。
