## 部署链路对齐（同 skin）

灰度帧 → 复制成 R=G=B → Pillow LANCZOS 拉伸到 512×512（上位机）→ 板端按档位取样（128 = `x[::4, ::4]`）→ 输出复制 4×4 回 512 →
PIL NEAREST 放回原图尺寸，在原分辨率上算 Dice（快捷算法与真实上采样逐像素一致，已抽查验证）。
训练增广不做翻转（视图方向有约定），旋转 ±15°、缩放 0.85–1.15、平移 ±8%、亮度 / 对比度 / gamma。

## F2 点击纠错（10-08，**已上板验收**）

**做法**：同一个 U-Net、同一个比特流，把三个输入通道重新编码，训练出模型库第 3 号模型 `echo_inter`：

| 通道 | 内容 |
|---|---|
| R | 超声帧（灰度） |
| G | 先验掩膜 0 / 255：第一步是 F1 自动分割的结果，之后是上一步的输出（F3 跟踪时可以换成上一帧的结果） |
| B | 有符号点击图 `round(128 + 127·正 − 128·负)`，每个点是半径 40 像素（512 画布）的锥形，板端 128 档取样后就是半径 10 的锥形 |

上位机把这三个通道拼成一张 512×512 的“RGB 图”发给板子（`tcp_image_ui/interactive.py`），**板端和比特流都不知道这是交互**。
上位机编码与训练编码逐字节相同（已对 5 个点击的组合核对，0 个像素不同）。

**训练**（`train_inter.py`，128 档，GPU 上模拟）：先验来源 v2 = F1 在训练序列每一帧上的真实预测 40% / 相邻帧标注 20% / 轻度扰动的本帧标注 25% / 空白 15%；
点击 0–6 个，落在先验剩余误差区域的内部（漏的点正点，多的点负点）。
v1（只用人为扰动的先验）会出现“第一次点击后反而比自动结果差”（0.926 < 0.920 附近），v2 用真实先验后解决（`results/selection_f2.json`）。
半周期序列里 ED/ES 以外帧的标注来源官方页面没写，只用于训练；**评测只用专家标注的 ED/ES 帧**。

**评测协议**（交互分割的标准做法）：每一步把点击放在当前最大误差连通域的中心（距离变换最大处），误差是漏检就点正点，否则负点；输出作为下一步的先验。
官方验证集 50 例 / 200 帧，原分辨率 Dice：

| 点击次数 | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---:|---:|---:|---:|---:|---:|
| 从 F1 自动结果出发，FP32 | 0.923 | 0.942 | 0.950 | 0.956 | 0.958 | 0.960 |
| **从 F1 自动结果出发，整数 = 板上实测** | **0.921** | **0.941** | **0.949** | **0.956** | **0.959** | **0.961** |
| 从空白出发，整数 = 板上实测 | 0.900 | 0.934 | 0.944 | 0.952 | 0.957 | 0.960 |

参照：F1 自动分割本身 0.9196。平均 0.34 次点击达到 Dice 0.90（从空白出发 0.63 次）。

**量化**：同一规则；校准用 8 个按训练方案模拟出来的三通道样本（种子 20260923）；INT16 确认用整数模型在验证集上跑点击循环。选中 `first_block_2` + `down_path_0_block_5`
（**`first_block_2` 第四次被选中**：眼底、皮肤、心超、心超交互），输出 scale 0.44012。

**逐值验证**：量化时记录的 2400 个点击循环输入（两种起点 × 6 步 × 200 帧）全部经 HLS 位级模拟器重算，0 差异；金标准输入 30 个节点 0 差异；512 整表 0 差异。

**上板**（v5.1，`tcp_image_rx/progress_and_handoff.md` §9.39）：
- `verify_board_inter.py`：2400 个输入在板上的输出全部与整数模型逐值一致，**板上测出的点击曲线与上表完全相同**；每次点击板端 AI 37.7 ms，往返约 112 ms。
- 界面（`tcp_image_ui/verify_board_v5_ui.py`）：选「心超左心室」、勾「点击纠错」→ 发送得到自动结果 → 左键正点、右键负点，每次 FPGA 重算；撤销 / 重置在本地恢复（不重跑 FPGA）；
  每一步板端报回模型 3，本地重算与板端逐字节一致。
- 回归：模型 0–2 的验收、三模型随机切换 60 帧、眼底 v4 客户端 75 帧都仍然通过。

**文件**：`gen_f1_priors.py`（F1 在序列上的预测，作真实先验）、`prep_camus_seq.py`（序列缓存）、`train_inter.py`、`quantize_inter.py`、`export_verify_inter.py`、`verify_board_inter.py`；

## F3 序列传播与跟踪（10-09，**已上板验收**，v5.2）

**做法**：上位机逐帧播放心超序列，每帧在 FPGA 上跑一次整网，**上一帧的结果作为这一帧的输入先验**：

| 步骤 | 模型（模型库） | 输入 |
|---|---|---|
| 第 0 帧 | 2 号 `echo_lv`（F1） | 灰度帧 |
| 之后每帧 | **4 号 `echo_seq`（新）** | R = 本帧，G = 上一步的结果 0 / 255，B = 128 |
| 暂停时点击纠正 | 3 号 `echo_inter`（F2） | R = 本帧，G = 当前结果，B = 点击锥形；之后从纠正后的结果继续传播 |

面积按板端掩膜换算回原图像素（像素间距来自 NIfTI 头 / `sequence.json`，换成 cm²）；面积最大的帧标 ED 候选、最小的标 ES 候选，FAC =（A_ED − A_ES）/ A_ED。
板端和比特流不知道这是序列，只是多了一套参数。

**1. 直接复用 F2 模型不行**（`eval_f3.py`，`results/f3/inter2_r128/`）：平滑但太“信”先验，跟不上收缩（正向 ES Dice 0.876，FAC 误差 17.2 个百分点）。

**2. 中间帧标注看起来是插值的**（`check_seq_labels.py` → `results/f3/label_shape.json`）：标注的左心室面积从 ED 到 ES 几乎是直线下降，
每段曲线偏离直线的最大值中位数只有 1.2–1.3%；F1 从图像看到的是“先平后降”（等容收缩期之后才开始射血），偏离直线 7.6–8.1%。训练集、验证集一致。
官方没写这些标注怎么来的，这里只是推断；因此最终训练**只用专家 ED / ES 帧当目标**，中间帧标注只作输入先验。评测本来就只用 ED / ES。

**3. 训练与选择**（`train_seq.py`、`seqeval.py`、`compare_f3.py` → `results/selection_f3.json`）。规则事先定好：
得分 = 0.5 ×（正向 ED→ES 传播到 ES 的 Dice + 反向 ES→ED 传播到 ED 的 Dice），起点都是 F1 在板上的结果，只用验证集 100 段序列：

| 候选（FP32） | 训练方式 | 得分 | 正向 ES Dice | 正向 FAC 误差 |
|---|---|---:|---:|---:|
| seq_prev / seq_none | 单步（先验来自 1–3 帧外），9000 步时停 | 0.918 / 0.917 | 0.896 / 0.897 | 12.4 / 11.9 |
| seq_prev_ro / seq_none_ro | + 自回放：模型自己先连推 1–7 步再训 | 0.926 / 0.928 | 0.910 / 0.912 | 9.7 / 9.8 |
| seq_prev_ex / **seq_none_ex** | + 只用专家帧当目标、自回放最长 24 步 | 0.929 / **0.934** | 0.914 / 0.920 | 7.2 / 7.6 |

`prev` = B 通道放上一帧原图，`none` = B 通道放 128；两者差别很小，按规则选中 `seq_none_ex`。

**4. 量化**：同一规则（校准 8 个模拟样本，种子 20261008；INT16 确认用整数模型在验证集上跑传播）。**这次全 INT8 最好，没有选 INT16 节点**
（前四个模型都选了 `first_block_2`）。输出 scale 0.56005。

**5. 结果**（验证集 100 段序列，整数模型 = 板上实测；F1 逐帧也是整数）：

| 指标 | F1 逐帧独立 | **正向传播 ED→ES** | 反向传播 ES→ED |
|---|---:|---:|---:|
| ED Dice（原分辨率） | 0.932 | 0.932（起点 = F1） | **0.940** |
| ES Dice | 0.907 | **0.920** | 0.907（起点 = F1） |
| ES Dice，好 / 中质量 | 0.912 | 0.924 | — |
| FAC 误差（已知哪帧是 ED/ES），百分点 | 5.7 | 6.0 | 7.3 |
| **自动 FAC 误差**（面积曲线最大 / 最小，不告诉 ED/ES） | 5.7 | **5.6** | 5.5 |
| 自动 FAC 与专家 FAC 的相关系数 | 0.756 | **0.797** | 0.777 |
| 面积最大帧正好是 ED / 最小帧正好是 ES | 41% / 46% | **60% / 62%** | 76% / 26% |
| 关键帧平均偏差（帧） | 1.34 | **0.88** | 1.30 |
| 帧间跳变 1 − Dice(相邻帧)，均值 / 95 分位 | 0.046 / 0.101 | **0.025 / 0.051** | 0.027 / 0.057 |
| 面积曲线粗糙度 | 0.056 | **0.028** | 0.031 |

参照：中间帧标注本身的帧间跳变 0.014（但它们像是插值的，见上）。
结论：正向传播（界面的默认用法）两端 Dice 不低于逐帧 F1、ES 更好；轮廓抖动减半；关键帧更准；自动 FAC 与 F1 持平、相关更高。
**没解决的**：起点 F1 在 ED 帧本身偏小约 4%（128 网格），所以正向传播头一两帧面积会先涨一点，ED 候选有 40% 落在第 1–2 帧；反向传播的 ES 候选只有 26% 正好落在最后一帧。
半周期序列的 ED / ES 本来就在两端，这里的“关键帧”只检验面积曲线是否单调、峰谷是否落对位置。

## F4 射血分数（10-09，**已上板验收**，界面功能；板端程序不变）

**做法**：分割在 FPGA 上——F1（2 号模型）给第 0 帧，F3（4 号）逐帧传播，可选 F2（3 号）点击纠正；
**关键帧选择和容积计算在 PC 上**：每个视图取面积曲线最大 / 最小的帧当 ED / ES，二腔心 + 四腔心两个视图用双平面 Simpson 圆盘法算
EDV、ESV，EF =（EDV − ESV）/ EDV。

**方法与 CAMUS 官方一致**：`tcp_image_ui/ef_simpson.py` 是 CAMUS 数据集自带笔记本 `jupyter/script_camus_ef.ipynb`
（Leclerc et al., IEEE TMI 2019；CC BY-NC-SA 4.0）的逐步移植，上位机和离线评测共用这一份代码（`echo/ef.py` 只是转引）。
主要步骤：
1. 转成各向同性像素；
2. 取第一条轮廓；
3. 二尖瓣平面取满足“方向偏离水平不超过 45°、中间轮廓点到连线都不超过 8 像素”的最长弦；
4. 离这条弦中点最远的轮廓点当心尖；
5. 沿长轴切 20 个圆盘量直径。

## F5 连续帧配准（拓展④，B 级；10-09，**已上板验收**，v5.3）

**各步在哪做**：

| 步骤 | 位置 | 做法 |
|---|---|---|
| 逐像素代价 \|a − b\| | **PL** | 同一个 30 节点网络，模型库 5 号 `reg_absdiff` 用**手工构造的参数**（不训练） |
| 每个候选的 SAD 求和 | **PS** | 新增标志位 b7：logit 图 4×4 分块的有符号和，作为 96 字节块跟在统计块后面 |
| 候选平移的生成、搜索、显示 | PC | 三步搜索（视频编码里的经典块匹配）或 ±7 全搜索 |

**手工参数怎么让同一个网络算 \|R − G\|**（`make_reg_model.py`）：
- 第一块卷积的中心抽头算出 R − G 和 G − R，经过 ReLU 后得到两路非负差；
- 全分辨率跳连上的桥接卷积和最后一个卷积块做恒等传递，再把两路相加，得到 \|R − G\|；
- 上采样那半边的权重全是 0，所以下采样各层的输出（保留随机初始化）乘 0 后不影响结果；
- 用到的都是中心抽头，每个输出像素只依赖同一位置的输入，因此 512 档一帧可以拼 **4×4 = 16 个互不影响的候选**（每块 128×128）。

**精度与逐值验证**：
- 浮点输出与 \|R − G\| 完全相等；
- 量化（全 INT8，输出 scale 1/127）后，整数 logit 与 \|a−b\|×127/255 的偏差 ≤ 1.49，即不到 3 个灰度级；
- 512 拼图一次算的结果与 16 次单独 128 计算逐值相同；
- HLS 位级模拟器：金标准 30 个节点、另外 43 个输入，全部 0 差异（`export_verify_reg.py`）。

**上位机的候选编码**（`tcp_image_ui/registration.py`，纯 Python）：
- 两帧都按板端 128 档取样；
- 候选 (dx, dy) 的 G 平面是平移后的 B，移出重叠区的像素填 A 自己的值（差为 0），所以分块和就是重叠区的 SAD；PC 再除以重叠面积，得到平均差。

和规划的区别：规划写的是由 PS 生成平移后的帧，实际改成 PC 拼好再发，这样协议不必改成一次传两幅图。
C 级（仿射变换、双线性插值和代价全在 PL）需要新的 HLS IP 并重建比特流，没有做。

**板上验收**（`verify_board_reg.py` → `board_check/acceptance_f5_reg.json`；CAMUS 验证集）：

| 测试 | 结果 |
|---|---|
| 逐值核对：20 帧、320 个候选 | PL 的 \|a−b\| 与整数参考 0 差异；PS 的 16 个分块和、变化像素计数（\|a−b\| ≥ 16）全部正确 |
| 已知平移：真实相邻帧 + 人为平移，128 网格 ±7（512 画布 ±28 像素） | 三步搜索 **100/100 完全找回**（每次 3 帧）；全搜索 **30/30**（每次 15 帧） |
| 同上，平均灰度差：不对齐 → 对齐到真值 | 17.9 → 6.3 |
| 真实相邻帧，不加平移（50 对） | 全部找到 (0, 0)，符合心超探头固定不动；平均灰度差 6.1 |
| ED 对 ES（50 对） | 也是 (0, 0)；平均灰度差 14.3，这是心肌收缩造成的非刚性形变，平移消除不了，差异图正好显示心脏的运动 |
| 速度 | 每帧往返 620 ms（板端推理 564 ms），**平均每个候选 38.7 ms**；PS 求和每帧 0.83 ms；三步搜索一次约 1.9 s，全搜索约 9.3 s |

**界面**：在序列窗口点「连续帧配准…」，可以选帧 A、帧 B，也可以给 B 加一个已知平移来演示能否找回。点「三步搜索」或「全搜索 ±7」后显示：
