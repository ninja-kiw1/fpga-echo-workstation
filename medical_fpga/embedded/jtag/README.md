# JTAG 上板验证（无操作系统）

不需要 SD 卡或任何板载系统。电脑通过 JTAG 直接完成 ARM 程序要做的事：下载 bitstream，执行 `psu_init`（时钟、DDR、PS-PL 隔离解除），把参数和输入写入 DDR，按 `network.txt` 逐层写寄存器、启动并等待完成，最后把指定节点读回电脑，与 HLS 参考逐字节比较。

## 用法

准备：FZ3B 断电，拨码开关 **SW1 四位全部拨到 ON**（JTAG 启动模式），接好 JTAG 下载器，上电。

```powershell
Set-Location E:\PLD\medical_fpga\embedded\jtag
$py = 'C:\Users\21888\anaconda3\envs\srtp-vision\python.exe'
& $py .\jtag_verify.py                                  # im0002，读回 9 个关键节点
& $py .\jtag_verify.py --image im0324 --dump final      # 其他图，只比对最终输出
& $py .\jtag_verify.py --readback-only --dump add cat   # 不重跑，读出上一次运行留在 DDR 里的节点
```

- `--dump all` 读回全部 30 个节点。只有 im0002 带逐节点 golden；其他图像只能比对 `final`。
- 每次运行的结果放在 `results/<时间>_<图像>/`：`run.tcl`（实际执行的 XSCT 脚本）、`xsct.log`、读回的 `*.bin` 和 `result.json`。
- 每个节点独占一块 DDR 缓冲区，从 `0x1000_0000` 开始，共 85.6 MiB，所以任意中间结果都能在运行结束后读回。

## JTAG 链路的问题与对策

这根下载器和板子之间的 JTAG 链路**不稳定**：
- 读回的数据里偶尔有零星错字（同一块数据反复读，错的位置每次都不同）；
- XSCT 还会报 `Invalid DAP IDCODE`、`Invalid DAP ACK`、`AXI AP transaction error`。15 MHz 和 10 MHz 下都很频繁，5 MHz 下仍然会出现。

这些是 JTAG 传输层的错误，不是加速器的问题。依据是：读回错误从不向下游传播，重读后数据正确，每次出错的位置也不相同。

脚本的对策：
1. **JTAG 时钟** 默认 5 MHz（`--jtag-hz`）；内存和寄存器访问走 APU 的内存访问端口，不经过 A53 核的调试接口（后者在长时间读回时丢失过调试上下文）。
2. **每次访问失败都重试**；寄存器写入后读回确认。
3. **上传**：用 `dow` 写入后，按 64 KiB 分块稳定读回，与源文件逐字节比较，不一致就重传。
4. **读回**：按 64 KiB 分块，每块连续两次读到相同内容才采用。
5. **进程级恢复**：连接出错后，在同一个 XSCT 进程里恢复不了调试上下文。因此：如果网络还没跑完，就换新进程从复位开始整轮重来（`--run-retries`）；如果网络已经跑完，就换新进程只补读缺失的节点（`--readback-retries`），DDR 里的数据不受影响。

建议检查 JTAG 连接：插紧排针、缩短连线、不经过 USB 集线器、确认板子供电稳定。链路稳定后可以试试提高 `--jtag-hz`，速度会快很多。

## 上板结果（2026-09-28，FZ3B，JTAG-SMT2）

芯片 IDCODE `0x14710093`（XSCT 显示为 xczu3）。按 xazu3eg 生成的 bitstream 能正常下载运行，之前担心的器件型号不兼容问题不存在。

**im0002：9 个关键节点全部逐值一致。** 网络运行一次（`20260928_233150_im0002`）后，所有数据都读自这一次运行留在 DDR 里的结果：

| 节点 | 类型 | 值数 | 差异 | 读回所在目录 |
|---|---|---:|---:|---|
| first_block_2 | 3×3 卷积，INT16 输出 | 2,097,152 | 0 | 233150 |
| add | Add | 2,097,152 | 0 | 233839 |
| down_path_0_pool | MaxPool | 524,288 | 0 | 233839 |
| add_2 | Add（32 通道） | 524,288 | 0 | 233839 |
| up_path_0_up_layer_block_0 | 转置卷积 | 1,048,576 | 0 | 233839 |
| cat | Concat | 2,097,152 | 0 | 233839 |
| up_path_0_conv_layer_block_2 | 3×3 卷积，INT16 输出 | 1,048,576 | 0 | 233839 |
| add_4 | Add | 2,097,152 | 0 | 233544 |
| final | 输出 1×1 卷积 | 2,097,152 | 0 | 233544 |

比较时包含补齐通道。更早一次运行（`232539`）从复位开始独立重跑，读回的 7 个节点同样全部一致。

**im0324**（Dice 最低的一张）：从复位开始独立运行一次（`20260928_234414_im0324`），最终输出 2,097,152 个值全部一致。

**速度**：每层耗时由电脑通过 JTAG 轮询测得，只是**上限**。计算量大的卷积层与周期模型的比值为 0.98～1.11；小节点被 JTAG 轮询开销（每次几毫秒）放大到 3～5 倍。各层上限之和约 500～640 ms，整网真实耗时估计在 450～500 ms/帧（100 MHz）。准确数字要等 ARM 程序在板上计时，比如用 PYNQ 或裸机程序。

**这次没有覆盖的**：其余 18 张图（可以用 `--image` 逐张运行，每张约 3 分钟）；ARM 上的调度程序；连续多帧运行和上位机通信。
