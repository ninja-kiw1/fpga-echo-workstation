## F3 逐位可复现（服务端 v5.21，`f3_repeat.py` → `f3_repeat.json / .log`）

EchoNet VAL 前 5 段，每段两种跑法（mode 2 关键帧推荐档、mode 0 每帧推理）各在板上重复 **20 次**，共 200 次。

| 检查 | 结果 |
| --- | --- |
| 同一段、同一跑法 20 次的结果哈希（去掉时间字段的全部结果 + 掩膜块） | **每组只有 1 个哈希**（10 / 10 组） |
| mode 2 与主机参考（同一份 C 编的 `echo_core.dll`）：关键帧序列、每帧掩膜、容积、EF | 100 / 100 次逐位相同 |
| 时间稳定性（推荐档整段任务） | 中位数 0.80–1.23 s，最慢一次比中位数多 1–3% |
| 每个关键帧的 PL 时间 | 22.8–24.0 ms（20 次的最小 / 最大） |
| 每个跟踪帧的 PS 时间 | 0.67–0.96 ms，同一段 20 次内相差 < 0.03 ms |

## F2 每帧预算（现场模式 v5.22 候选，`f2_f4_report.py` → `f2_budget.json`）

信号源 `0X100009310A3BD7FC`（174 帧，50 fps，帧间隔 20 ms），固定裁切，板上逐帧时间戳。

| 步骤 | 在哪 | 推荐档：每次 × 占帧比例 = 每帧平均 | 每帧推理 |
| --- | --- | --- | --- |
| 缩放（裁切 + 盒滤波到 112） | PS 采集线程（与处理并行） | 2.65 ms × 100% = 2.65 ms | 2.69 ms |
| PL 推理（t3 编码 + U-Net + pp_layer 清理） | PL（处理线程等它） | 23.0 ms × 17.8% = **4.10 ms** | 22.9 ms × 100% = **22.9 ms** |
| PS 跟踪（块匹配 + 轮廓 + 填充） | PS 处理线程 | 0.77 ms × 82.2% = 0.63 ms | — |
| 收尾（容积等） | PS 处理线程 | 0.37 ms | 1.42 ms |
| **处理线程合计** | | **5.1 ms / 帧 = 预算的 26%** | **24.3 ms / 帧 = 预算的 121%** |
| 延迟（采到 → 掩膜 + 容积） | | 中位数 29 ms，P99 67 ms，不累积 | 一路涨到 841 ms |

- 推荐档每帧剩下约 15 ms（74%）没用，可以留给右心程序、显示等。
- 延迟里有两段是"等"，不是"算"：关键帧要等第 t+d 帧（t3 编码看 40 ms 后，平均 39 ms），关键帧之后的两三帧要排队等它算完（平均 13 ms）。

## F4 异构并行（`f4_gantt.png`、`f4_latency.png`）

- 甘特图（1 s 窗口）：采集线程每 20 ms 缩放一帧（灰），处理线程上 PL 推理（蓝）、PS 跟踪（橙）、收尾（绿）。
  推荐档里处理线程大段空闲；每帧推理时处理线程被 PL 占满、没有空隙。
- **如实说**：PL 推理时处理线程在等 PL（不是同时跟踪别的帧），真正并行的是"采集 / 缩放线程"与"处理线程"，以及 PL 与 PS 采集线程。
  要让 PL 与 PS 跟踪重叠，需要改调度（关键帧推理的同时先跟踪后面的帧，再校正），会改变结果，没做。
- 延迟图：推荐档呈锯齿（每个关键帧处升到约 67 ms，随后几帧回落到几 ms），每帧推理呈直线上升。
